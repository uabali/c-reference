<p>Implementation defined behavior is controlled by <code>#pragma</code> directive.</p>

<h3 id="Syntax">Syntax</h3>

```text
#pragma pragma_params
_Pragma ( string-literal )
```

<p class="li-note"><span class="li-num">1)</span>  Behaves in an implementation-defined manner (unless <em>pragma_params</em> is one of the standard pragmas shown below).</p>

<p class="li-note"><span class="li-num">2)</span>  Removes the encoding prefix (if any), the outer quotes, and leading/trailing whitespace from <em>string-literal</em>, replaces each <code>\&quot;</code> with <code>&quot;</code> and each <code>\\</code> with <code>\</code>, then tokenizes the result (as in <a href="/reference/c/language/translation_phases/">translation stage 3</a>), and then uses the result as if the input to <code>#pragma</code> in (1).</p>

<h3 id="Explanation">Explanation</h3>

<p>The pragma directive controls implementation-specific behavior of the compiler, such as disabling compiler warnings or changing alignment requirements. Any pragma that is not recognized is ignored.</p>

<h3 id="Standard_pragmas">Standard pragmas</h3>

<p>The following three pragmas are defined by the language standard:</p>

```text
#pragma STDC FENV_ACCESS arg
#pragma STDC FP_CONTRACT arg
#pragma STDC CX_LIMITED_RANGE arg
```

<p>where <em>arg</em> is either <code>ON</code> or <code>OFF</code> or <code>DEFAULT</code>.</p>

<p class="li-note"><span class="li-num">1)</span>  If set to <code>ON</code>, informs the compiler that the program will access or modify <a href="/reference/c/numeric/fenv/">floating-point environment</a>, which means that optimizations that could subvert flag tests and mode changes (e.g., global common subexpression elimination, code motion, and constant folding) are prohibited. The default value is implementation-defined, usually <code>OFF</code>.</p>

<p class="li-note"><span class="li-num">2)</span>  Allows <em>contracting</em> of floating-point expressions, that is optimizations that omit rounding errors and floating-point exceptions that would be observed if the expression was evaluated exactly as written. For example, allows the implementation of <code>(x * y) + z</code> with a single fused multiply-add CPU instruction. The default value is implementation-defined, usually <code>ON</code>.</p>

<p class="li-note"><span class="li-num">3)</span>  Informs the compiler that multiplication, division, and absolute value of complex numbers may use simplified mathematical formulas (x+iy)×(u+iv) = (xu-yv)+i(yu+xv), (x+iy)/(u+iv) = [(xu+yv)+i(yu-xv)]/(u2 +v2 ), and |x+iy| = √x2 +y2 , despite the possibility of intermediate overflow. In other words, the programmer guarantees that the range of the values that will be passed to those function is limited. The default value is <code>OFF</code></p>

<p>Note: compilers that do not support these pragmas may provide equivalent compile-time options, such as gcc's <code>-fcx-limited-range</code> and <code>-ffp-contract</code>.</p>

<h3 id="Non-standard_pragmas">Non-standard pragmas</h3>

<h4 id=".23pragma_once"><code>#pragma once</code></h4>

<p><code>#pragma once</code> is a non-standard pragma that is supported by the <a href="https://en.wikipedia.org/wiki/Pragma_once#Portability" rel="noreferrer" target="_blank">vast majority of modern compilers</a>. If it appears in a header file, it indicates that it is only to be parsed once, even if it is (directly or indirectly) included multiple times in the same source file.</p>

<p>Standard approach to preventing multiple inclusion of the same header is by using <a href="https://en.wikipedia.org/wiki/Include_guard" rel="noreferrer" target="_blank">include guards</a>:</p>

```c
#ifndef LIBRARY_FILENAME_H
#define LIBRARY_FILENAME_H
// contents of the header
#endif /* LIBRARY_FILENAME_H */
```

<p>So that all but the first inclusion of the header in any translation unit are excluded from compilation. All modern compilers record the fact that a header file uses an include guard and do not re-parse the file if it is encountered again, as long as the guard is still defined (see e.g. <a href="https://gcc.gnu.org/onlinedocs/cpp/Once-Only-Headers.html" rel="noreferrer" target="_blank">gcc</a>).</p>

<p>With <code>#pragma once</code>, the same header appears as</p>

```c
#pragma once
// contents of the header
```

<p>Unlike header guards, this pragma makes it impossible to erroneously use the same macro name in more than one file. On the other hand, since with <code>#pragma once</code> files are excluded based on their filesystem-level identity, this can't protect against including a header twice if it exists in more than one location in a project.</p>

<h4 id=".23pragma_pack"><code>#pragma pack</code></h4>

<p>This family of pragmas control the maximum alignment for subsequently defined structure and union members.</p>

```text
#pragma pack(arg)
#pragma pack()
#pragma pack(push)
#pragma pack(push, arg)
#pragma pack(pop)
```

<p>where <em>arg</em> is a small power of two and specifies the new alignment in bytes.</p>

<p class="li-note"><span class="li-num">1)</span>  Sets the current alignment to value <em>arg</em>.</p>

<p class="li-note"><span class="li-num">2)</span>  Sets the current alignment to the default value (specified by a command-line option).</p>

<p class="li-note"><span class="li-num">3)</span>  Pushes the value of the current alignment on an internal stack.</p>

<p class="li-note"><span class="li-num">4)</span>  Pushes the value of the current alignment on the internal stack and then sets the current alignment to value <em>arg</em>.</p>

<p class="li-note"><span class="li-num">5)</span>  Pops the top entry from the internal stack and then sets (restores) the current alignment to that value.</p>

<p><code>#pragma pack</code> may decrease the alignment of a structure, however, it cannot make a structure overaligned.</p>

<p>See also specific details for <a href="https://gcc.gnu.org/onlinedocs/gcc/Structure-Layout-Pragmas.html" rel="noreferrer" target="_blank">GCC</a> and <a href="https://docs.microsoft.com/en-us/cpp/preprocessor/pack" rel="noreferrer" target="_blank">MSVC</a>.</p>
