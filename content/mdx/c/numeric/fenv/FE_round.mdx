<p class="decl-header">Defined in header <code>&lt;fenv.h&gt;</code></p>

```c
#define FE_DOWNWARD     /*implementation defined*/
```

<p class="decl-note"><span class="std std-since std-c99">(since C99)</span></p>

```c
#define FE_TONEAREST    /*implementation defined*/
```

<p class="decl-note"><span class="std std-since std-c99">(since C99)</span></p>

```c
#define FE_TOWARDZERO   /*implementation defined*/
```

<p class="decl-note"><span class="std std-since std-c99">(since C99)</span></p>

```c
#define FE_UPWARD       /*implementation defined*/
```

<p class="decl-note"><span class="std std-since std-c99">(since C99)</span></p>

<p>Each of these macro constants expands to a nonnegative integer constant expression, which can be used with <a href="/reference/c/numeric/fenv/feround/">fesetround</a> and <a href="/reference/c/numeric/fenv/feround/">fegetround</a> to indicate one of the supported floating-point rounding modes. The implementation may define additional rounding mode constants in <a href="/reference/c/numeric/fenv/"><code>&lt;fenv.h&gt;</code></a>, which should all begin with <code>FE_</code> followed by at least one uppercase letter. Each macro is only defined if it is supported.</p>

<table class="ref-table ref-dsc">
<tr><td>Constant</td><td>Explanation</td></tr>
<tr><td><code>FE_DOWNWARD</code></td><td>rounding towards negative infinity</td></tr>
<tr><td><code>FE_TONEAREST</code></td><td>rounding towards nearest representable value</td></tr>
<tr><td><code>FE_TOWARDZERO</code></td><td>rounding towards zero</td></tr>
<tr><td><code>FE_UPWARD</code></td><td>rounding towards positive infinity</td></tr>
</table>

<p>Additional rounding modes may be supported by an implementation.</p>

<p>The current rounding mode affects the following:</p>

<ul>
<li>
<p>results of floating-point arithmetic operators outside of constant expressions</p>
</li>
</ul>

```c
double x = 1;
x / 10; // 0.09999999999999999167332731531132594682276248931884765625 or
        // 0.1000000000000000055511151231257827021181583404541015625
```

<ul>
<li>
<p>results of standard library</p>

<a href="/reference/c/numeric/math/">mathematical functions</a>
</li>
</ul>

```c
sqrt(2); // 1.41421356237309492343001693370752036571502685546875 or
         // 1.4142135623730951454746218587388284504413604736328125
```

<ul>
<li>
<p>floating-point to floating-point implicit conversion and casts</p>
</li>
</ul>

```c
double d = 1 + DBL_EPSILON;
float f = d; // 1.00000000000000000000000 or
             // 1.00000011920928955078125
```

<ul>
<li>
<p>string conversions such as</p>

<a href="/reference/c/string/byte/strtof/">strtod</a>

<p>or</p>

<a href="/reference/c/io/fprintf/">printf</a>
</li>
</ul>

```c
strtof("0.1", NULL); // 0.0999999940395355224609375 or
                     // 0.100000001490116119384765625
```

<ul>
<li>
<p>the library rounding functions</p>

<a href="/reference/c/numeric/math/nearbyint/">nearbyint</a>

<p>,</p>

<a href="/reference/c/numeric/math/rint/">rint</a>

<p>,</p>

<a href="/reference/c/numeric/math/rint/">lrint</a>
</li>
</ul>

```c
lrint(2.1); // 2 or 3
```

<p>The current rounding mode does NOT affect the following:</p>

<ul>
<li>
<p>floating-point to integer implicit conversion and casts (always towards zero)</p>
</li>
<li>
<p>results of floating-point arithmetic operators in constant expressions executed at compile time (always to nearest)</p>
</li>
<li>
<p>the library functions</p>

<a href="/reference/c/numeric/math/round/">round</a>

<p>,</p>

<a href="/reference/c/numeric/math/round/">lround</a>

<p>,</p>

<a href="/reference/c/numeric/math/round/">llround</a>

<p>,</p>

<a href="/reference/c/numeric/math/ceil/">ceil</a>

<p>,</p>

<a href="/reference/c/numeric/math/floor/">floor</a>

<p>,</p>

<a href="/reference/c/numeric/math/trunc/">trunc</a>
</li>
</ul>

<p>As with any <a href="/reference/c/numeric/fenv/">floating-point environment</a> functionality, rounding is only guaranteed if <code>#pragma STDC FENV_ACCESS ON</code> is set.</p>

<p>Compilers that do not support the pragma may offer their own ways to support current rounding mode. For example Clang and GCC have the option <code>-frounding-math</code> intended to disable optimizations that would change the meaning of rounding-sensitive code.</p>

<h3 id="Example">Example</h3>

```c
#include <fenv.h>
#include <math.h>
#include <stdio.h>
#include <stdlib.h>
 
// #pragma STDC FENV_ACCESS ON
 
int main()
{
    fesetround(FE_DOWNWARD);
    puts("rounding down: ");
    printf("           pi = %.22f\n", acosf(-1));
    printf("strtof(\"1.1\") = %.22f\n", strtof("1.1", NULL));
    printf("    rint(2.1) = %.22f\n\n", rintf(2.1));
    fesetround(FE_UPWARD);
    puts("rounding up: ");
    printf("           pi = %.22f\n", acosf(-1));
    printf("strtof(\"1.1\") = %.22f\n", strtof("1.1", NULL));
    printf("    rint(2.1) = %.22f\n", rintf(2.1));
}
```

<p>Output:</p>

```text
rounding down:
           pi = 3.1415925025939941406250
strtof("1.1") = 1.0999999046325683593750
    rint(2.1) = 2.0000000000000000000000
 
rounding up:
           pi = 3.1415927410125732421875
strtof("1.1") = 1.1000000238418579101563
    rint(2.1) = 3.0000000000000000000000
```
