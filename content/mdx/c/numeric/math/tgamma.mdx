<p class="decl-header">Defined in header <code>&lt;math.h&gt;</code></p>

```c
float       tgammaf( float arg );
```

<p class="decl-note">(1) <span class="std std-since std-c99">(since C99)</span></p>

```c
double      tgamma( double arg );
```

<p class="decl-note">(2) <span class="std std-since std-c99">(since C99)</span></p>

```c
long double tgammal( long double arg );
```

<p class="decl-note">(3) <span class="std std-since std-c99">(since C99)</span></p>

<p class="decl-header">Defined in header <code>&lt;tgmath.h&gt;</code></p>

```c
#define tgamma( arg )
```

<p class="decl-note">(4) <span class="std std-since std-c99">(since C99)</span></p>

<p class="li-note"><span class="li-num">1-3)</span>  Computes the <a href="https://en.wikipedia.org/wiki/Gamma_function" rel="noreferrer" target="_blank">gamma function</a> of <code>arg</code>.</p>

<p class="li-note"><span class="li-num">4)</span>  Type-generic macro: If <code>arg</code> has type <code>long double</code>, <code>tgammal</code> is called. Otherwise, if <code>arg</code> has integer type or the type <code>double</code>, <code>tgamma</code> is called. Otherwise, <code>tgammaf</code> is called.</p>

<h3 id="Parameters">Parameters</h3>

<table class="ref-table ref-params">
<tr><td>arg</td><td>-</td><td>floating-point value</td></tr>
</table>

<h3 id="Return_value">Return value</h3>

<p>If no errors occur, the value of the gamma function of <code>arg</code>, that is \(\Gamma(\mathtt{arg}) = \displaystyle\int_0^\infty\!\! t^{\mathtt{arg}-1} e^{-t}\, dt\)∫∞ 0<em>t</em>arg-1  <em>e</em><sup>-t</sup> d<em>t</em>, is returned.</p>

<p>If a domain error occurs, an implementation-defined value (NaN where supported) is returned.</p>

<p>If a pole error occurs, <code>±HUGE_VAL</code>, <code>±HUGE_VALF</code>, or <code>±HUGE_VALL</code> is returned.</p>

<p>If a range error due to overflow occurs, <a href="/reference/c/numeric/math/HUGE_VAL/">±HUGE_VAL</a>, <code>±HUGE_VALF</code>, or <code>±HUGE_VALL</code> is returned.</p>

<p>If a range error due to underflow occurs, the correct value (after rounding) is returned.</p>

<h3 id="Error_handling">Error handling</h3>

<p>Errors are reported as specified in <a href="/reference/c/numeric/math/math_errhandling/"><code>math_errhandling</code></a>.</p>

<p>If <code>arg</code> is zero or is an integer less than zero, a pole error or a domain error may occur.</p>

<p>If the implementation supports IEEE floating-point arithmetic (IEC 60559):</p>

<ul>
<li>
<p>If the argument is ±0, ±∞ is returned and</p>

<a href="/reference/c/numeric/fenv/FE_exceptions/">FE_DIVBYZERO</a>

<p>is raised.</p>
</li>
<li>
<p>If the argument is a negative integer, NaN is returned and</p>

<a href="/reference/c/numeric/fenv/FE_exceptions/">FE_INVALID</a>

<p>is raised.</p>
</li>
<li>
<p>If the argument is -∞, NaN is returned and</p>

<a href="/reference/c/numeric/fenv/FE_exceptions/">FE_INVALID</a>

<p>is raised.</p>
</li>
<li>
<p>If the argument is +∞, +∞ is returned.</p>
</li>
<li>
<p>If the argument is NaN, NaN is returned.</p>
</li>
</ul>

<h3 id="Notes">Notes</h3>

<p>If <code>arg</code> is a natural number, <code>tgamma(arg)</code> is the factorial of <code>arg - 1</code>. Many implementations calculate the exact integer-domain factorial if the argument is a sufficiently small integer.</p>

<p>For IEEE-compatible type <code>double</code>, overflow happens if <code>0 &lt; x &lt; 1/DBL_MAX</code> or if <code>x &gt; 171.7</code>.</p>

<p><a href="https://pubs.opengroup.org/onlinepubs/9699919799/functions/tgamma.html" rel="noreferrer" target="_blank">POSIX requires</a> that a pole error occurs if the argument is zero, but a domain error occurs when the argument is a negative integer. It also specifies that in future, domain errors may be replaced by pole errors for negative integer arguments (in which case the return value in those cases would change from NaN to ±∞).</p>

<p>There is a non-standard function named <code>gamma</code> in various implementations, but its definition is inconsistent. For example, glibc and 4.2BSD version of <code>gamma</code> executes <code>lgamma</code>, but 4.4BSD version of <code>gamma</code> executes <code>tgamma</code>.</p>

<h3 id="Example">Example</h3>

```c
#include <errno.h>
#include <fenv.h>
#include <float.h>
#include <math.h>
#include <stdio.h>
// #pragma STDC FENV_ACCESS ON
 
int main(void)
{
    printf("tgamma(10) = %f, 9!=%f\n", tgamma(10), 2 * 3 * 4 * 5 * 6 * 7 * 8 * 9.0);
    printf("tgamma(0.5) = %f, sqrt(pi) = %f\n", tgamma(0.5), sqrt(acos(-1)));
 
    // special values
    printf("tgamma(+Inf) = %f\n", tgamma(INFINITY));
 
    // error handling
    errno = 0; feclearexcept(FE_ALL_EXCEPT);
    printf("tgamma(-1) = %f\n", tgamma(-1));
    if (errno == ERANGE)
        perror("    errno == ERANGE");
    else
        if (errno == EDOM)   perror("    errno == EDOM");
    if (fetestexcept(FE_DIVBYZERO))
        puts("    FE_DIVBYZERO raised");
    else if (fetestexcept(FE_INVALID))
        puts("    FE_INVALID raised");
}
```

<p>Possible output:</p>

```text
tgamma(10) = 362880.000000, 9!=362880.000000
tgamma(0.5) = 1.772454, sqrt(pi) = 1.772454
tgamma(+Inf) = inf
tgamma(-1) = nan
    errno == EDOM: Numerical argument out of domain
    FE_INVALID raised
```
