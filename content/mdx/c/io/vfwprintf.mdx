<p class="decl-note">(7) <span class="std std-since std-c11">(since C11)</span></p>

<p>Loads the data from locations, defined by <code>vlist</code>, converts them to wide string equivalents and writes the results to a variety of sinks.</p>

<p class="li-note"><span class="li-num">1)</span>  Writes the results to <a href="/reference/c/io/std_streams/">stdout</a>.</p>

<p class="li-note"><span class="li-num">2)</span>  Writes the results to a file stream <code>stream</code>.</p>

<p class="li-note"><span class="li-num">3)</span>  Writes the results to a wide string <code>buffer</code>. At most <code>bufsz - 1</code> wide characters are written followed by null wide character. The resulting wide character string will be terminated with a null wide character, unless <code>bufsz</code> is zero.</p>

<p>The floating-point conversion functions convert infinity to <code>inf</code> or <code>infinity</code>. Which one is used is implementation defined.</p>

<p>Not-a-number is converted to <code>nan</code> or <code>nan(char_sequence)</code>. Which one is used is implementation defined.</p>

<p>The conversions <code>F</code>, <code>E</code>, <code>G</code>, <code>A</code> output <code>INF</code>, <code>INFINITY</code>, <code>NAN</code> instead.</p>

<p>The conversion specifier used to print <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code> expects promoted types of <a href="/reference/c/language/conversion/#Default_argument_promotions">default argument promotions</a>, but before printing its value will be converted to <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code>. It is safe to pass values of these types because of the promotion that takes place when a variadic function is called.</p>

<p>The correct conversion specifications for the fixed-width character types (<a href="/reference/c/types/integer/">int8_t</a>, etc) are defined in the header <a href="/reference/c/types/integer/"><code>&lt;inttypes.h&gt;</code></a> (although <a href="/reference/c/types/integer/">PRIdMAX</a>, <a href="/reference/c/types/integer/">PRIuMAX</a>, etc is synonymous with <code>%jd</code>, <code>%ju</code>, etc).</p>

<p>The memory-writing conversion specifier <code>%n</code> is a common target of security exploits where format strings depend on user input and is not supported by the bounds-checked <code>printf_s</code> family of functions.</p>

<p>There is a <a href="/reference/c/language/eval_order/">sequence point</a> after the action of each conversion specifier; this permits storing multiple <code>%n</code> results in the same variable or, as an edge case, printing a string modified by an earlier <code>%n</code> within the same call.</p>

<p>If a conversion specification is invalid, the behavior is undefined.</p>

<h3 id="Return_value">Return value</h3>

<p class="li-note"><span class="li-num">1,4)</span>  The number of wide characters written if successful or negative value if an error occurred.</p>

<p class="li-note"><span class="li-num">3)</span>  The number of wide characters written if successful or negative value if an error occurred. If the resulting string gets truncated due to <code>bufsz</code> limit, function returns the total number of characters (not including the terminating null wide character) which would have been written, if the limit were not imposed.</p>

<p class="li-note"><span class="li-num">2,5)</span>  number of wide characters transmitted to the output stream or negative value if an output error, a runtime constraints violation error, or an encoding error occurred.</p>

<p class="li-note"><span class="li-num">6)</span>  number of wide characters written to <code>buffer</code>, not counting the null wide character (which is always written as long as <code>buffer</code> is not a null pointer and <code>bufsz</code> is not zero and not greater than <code>RSIZE_MAX/sizeof(wchar_t)</code>), or zero on runtime constraint violations, and negative value on encoding errors.</p>

<p class="li-note"><span class="li-num">7)</span>  number of wide characters not including the terminating null character (which is always written as long as <code>buffer</code> is not a null pointer and <code>bufsz</code> is not zero and not greater than <code>RSIZE_MAX/sizeof(wchar_t)</code>), which would have been written to <code>buffer</code> if <code>bufsz</code> was ignored, or a negative value if a runtime constraints violation or an encoding error occurred.</p>

<h3 id="Notes">Notes</h3>

<p>All these functions invoke va_arg at least once, the value of <code>arg</code> is indeterminate after the return. These functions to not invoke va_end, and it must be done by the caller.</p>

<p>While narrow strings provide <a href="/reference/c/io/vfprintf/">vsnprintf</a>, which makes it possible to determine the required output buffer size, there is no equivalent for wide strings (until C11's vsnwprintf_s), and in order to determine the buffer size, the program may need to call <code>vswprintf</code>, check the result value, and reallocate a larger buffer, trying again until successful.</p>

<p><code>vsnwprintf_s</code>, unlike <code>vswprintf_s</code>, will truncate the result to fit within the array pointed to by <code>buffer</code>, even though truncation is treated as an error by most bounds-checked functions.</p>

<h3 id="Example">Example</h3>

```c
#include <locale.h>
#include <stdarg.h>
#include <stddef.h>
#include <stdio.h>
#include <time.h>
#include <wchar.h>
 
void debug_wlog(const wchar_t* fmt, ...)
{
    struct timespec ts;
    timespec_get(&ts, TIME_UTC);
    char time_buf[100];
    size_t rc = strftime(time_buf, sizeof time_buf, "%D %T", gmtime(&ts.tv_sec));
    snprintf(time_buf + rc, sizeof time_buf - rc, ".%06ld UTC", ts.tv_nsec / 1000);
 
    va_list args;
    va_start(args, fmt);
    wchar_t buf[1024];
    int rc2 = vswprintf(buf, sizeof buf / sizeof *buf, fmt, args);
    va_end(args);
 
    if(rc2 > 0)
       wprintf(L"%s [debug]: %ls\n", time_buf, buf);
    else
       wprintf(L"%s [debug]: (string too long)\n", time_buf);
}
 
int main(void)
{
    setlocale(LC_ALL, "");
    debug_wlog(L"Logging, %d, %d, %d", 1, 2, 3);
}
```

<p>Possible output:</p>

```text
02/20/15 22:12:38.476575 UTC [debug]: Logging, 1, 2, 3
```
