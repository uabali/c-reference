<p class="decl-note">(7) <span class="std std-since std-c11">(since C11)</span></p>

<p>Loads the data from the given locations, converts them to wide string equivalents and writes the results to a variety of sinks.</p>

<p class="li-note"><span class="li-num">1)</span>  Writes the results to <a href="/reference/c/io/std_streams/">stdout</a>.</p>

<p class="li-note"><span class="li-num">2)</span>  Writes the results to a file stream <code>stream</code>.</p>

<p class="li-note"><span class="li-num">3)</span>  If <code>bufsz</code> is greater than zero, writes the results to a wide string <code>buffer</code>. At most <code>bufsz - 1</code> wide characters are written followed by null wide character. If <code>bufsz</code> is zero, nothing is written (and <code>buffer</code> may be a null pointer).</p>

<p>The floating-point conversion functions convert infinity to <code>inf</code> or <code>infinity</code>. Which one is used is implementation defined.</p>

<p>Not-a-number is converted to <code>nan</code> or <code>nan(char_sequence)</code>. Which one is used is implementation defined.</p>

<p>The conversions <code>F</code>, <code>E</code>, <code>G</code>, <code>A</code> output <code>INF</code>, <code>INFINITY</code>, <code>NAN</code> instead.</p>

<p>The conversion specifier used to print <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code> expects promoted types of <a href="/reference/c/language/conversion/#Default_argument_promotions">default argument promotions</a>, but before printing its value will be converted to <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code>. It is safe to pass values of these types because of the promotion that takes place when a variadic function is called.</p>

<p>The correct conversion specifications for the fixed-width character types (<a href="/reference/c/types/integer/">int8_t</a>, etc) are defined in the header <a href="/reference/c/types/integer/"><code>&lt;inttypes.h&gt;</code></a> (although <a href="/reference/c/types/integer/">PRIdMAX</a>, <a href="/reference/c/types/integer/">PRIuMAX</a>, etc is synonymous with <code>%jd</code>, <code>%ju</code>, etc).</p>

<p>The memory-writing conversion specifier <code>%n</code> is a common target of security exploits where format strings depend on user input and is not supported by the bounds-checked <code>printf_s</code> family of functions.</p>

<p>There is a <a href="/reference/c/language/eval_order/">sequence point</a> after the action of each conversion specifier; this permits storing multiple <code>%n</code> results in the same variable or, as an edge case, printing a string modified by an earlier <code>%n</code> within the same call.</p>

<p>If a conversion specification is invalid, the behavior is undefined.</p>

<h3 id="Return_value">Return value</h3>

<p class="li-note"><span class="li-num">1,2)</span>  Number of wide characters written if successful or negative value if an error occurred.</p>

<p class="li-note"><span class="li-num">3)</span>  Number of wide characters written (not counting the terminating null wide character) if successful or negative value if an encoding error occurred or if the number of characters to be generated was equal or greater than <code>bufsz</code> (including when <code>bufsz</code> is zero).</p>

<p class="li-note"><span class="li-num">4,5)</span>  Number of wide characters written if successful or negative value if an error occurred.</p>

<p class="li-note"><span class="li-num">6)</span>  Number of wide characters (not counting the terminating null) that were written to <code>buffer</code>. Returns a negative value on encoding errors and on overflow. Returns zero on all other errors.</p>

<p class="li-note"><span class="li-num">7)</span>  Number of wide characters (not counting the terminating null) that would have been written to <code>buffer</code> had <code>bufsz</code> been sufficiently large, or a negative value if an error occurs. (meaning, write was successful and complete only if the return is nonnegative and less than <code>bufsz</code>)</p>

<h3 id="Notes">Notes</h3>

<p>While narrow strings provide <a href="/reference/c/io/fprintf/">snprintf</a>, which makes it possible to determine the required output buffer size, there is no equivalent for wide strings (until <code>snwprintf_s</code>)<span class="std std-since std-c11">(since C11)</span>, and in order to determine the buffer size, the program may need to call <code>swprintf</code>, check the result value, and reallocate a larger buffer, trying again until successful.</p>

<p><code>snwprintf_s</code>, unlike <code>swprintf_s</code>, will truncate the result to fit within the array pointed to by <code>buffer</code>, even though truncation is treated as an error by most bounds-checked functions.</p>

<h3 id="Example">Example</h3>

```c
#include <locale.h>
#include <wchar.h>
 
int main(void)
{
    char narrow_str[] = "z\u00df\u6c34\U0001f34c";
                  // or "zß水🍌"
                  // or "\x7a\xc3\x9f\xe6\xb0\xb4\xf0\x9f\x8d\x8c";
    wchar_t warr[29]; // the expected string is 28 characters plus 1 null terminator
    setlocale(LC_ALL, "en_US.utf8");
    swprintf(warr, sizeof warr / sizeof* warr,
             L"Converted from UTF-8: '%s'", narrow_str);
    wprintf(L"%ls\n", warr);
}
```

<p>Output:</p>

```text
Converted from UTF-8: 'zß水🍌'
```
