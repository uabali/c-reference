<p class="decl-header">Defined in header <code>&lt;stdio.h&gt;</code></p>

<p class="decl-note">(1)</p>

```c
int scanf( const char          *format, ... );
```

```c

```

<p class="decl-note"><span class="std std-since std-c99">(since C99)</span></p>

```c

```

```c

```


<p class="decl-note">(6) <span class="std std-since std-c11">(since C11)</span></p>

<p>Reads data from a variety of sources, interprets it according to <code>format</code> and stores the results into given locations.</p>

<p class="li-note"><span class="li-num">1)</span>  reads the data from <a href="/reference/c/io/std_streams/">stdin</a></p>

<p class="li-note"><span class="li-num">2)</span>  reads the data from file stream <code>stream</code></p>

<p class="li-note"><span class="li-num">3)</span>  reads the data from null-terminated character string <code>buffer</code>. Reaching the end of the string is equivalent to reaching the end-of-file condition for <code>fscanf</code></p>

<div class="li-note"><span class="li-num">4-6)</span>

<p>Same as</p>

(1-3)

<p>, except that</p>

<code>%c</code>

<p>,</p>

<code>%s</code>

<p>, and</p>

<code>%[</code>

<p>conversion specifiers each expect two arguments (the usual pointer and a value of type</p>

rsize_t

<p>indicating the size of the receiving array, which may be</p>

<code>1</code>

<p>when reading with a</p>

<code>%c</code>

<p>into a single char) and except that the following errors are detected at runtime and call the currently installed</p>

<a href="/reference/c/error/set_constraint_handler_s/">constraint handler</a>

<p>function:</p>

<dl>
<dd><ul>
<li>
<p>any of the arguments of pointer type is a null pointer</p>
</li>
<li>
<code>format</code>

<p>,</p>

<code>stream</code>

<p>, or</p>

<code>buffer</code>

<p>is a null pointer</p>
</li>
<li>
<p>the number of characters that would be written by</p>

<code>%c</code>

<p>,</p>

<code>%s</code>

<p>, or</p>

<code>%[</code>

<p>, plus the terminating null character, would exceed the second (</p>

<code>rsize_t</code>

<p>) argument provided for each of those conversion specifiers</p>
</li>
<li>
<p>optionally, any other detectable error, such as unknown conversion specifier</p>
</li>
</ul></dd>
<dd><p>As with all bounds-checked functions,</p>

<code>scanf_s</code>

<p>,</p>

<code>fscanf_s</code>

<p>, and</p>

<code>sscanf_s</code>

<p>are only guaranteed to be available if</p>

<code>__STDC_LIB_EXT1__</code>

<p>is defined by the implementation and if the user defines</p>

<code>__STDC_WANT_LIB_EXT1__</code>

<p>to the integer constant</p>

<code>1</code>

<p>before including</p>

<a href="/reference/c/io/"><code>&lt;stdio.h&gt;</code></a>

<p>.</p></dd>
</dl></div>

<p>The <strong>format</strong> string consists of</p>

<ul>
<li>
<p>non-whitespace multibyte characters except</p>

<code>%</code>

<p>: each such character in the format string consumes exactly one identical character from the input stream, or causes the function to fail if the next character on the stream does not compare equal.</p>
</li>
<li>
<p>whitespace characters: any single whitespace character in the format string consumes all available consecutive whitespace characters from the input (determined as if by calling</p>

<a href="/reference/c/string/byte/isspace/"><code>isspace</code></a>

<p>in a loop). Note that there is no difference between</p>

<code>&quot;\n&quot;</code>

<p>,</p>

<code>&quot; &quot;</code>

<p>,</p>

<code>&quot;\t\t&quot;</code>

<p>, or other whitespace in the format string.</p>
</li>
<li>
<p>conversion specifications. Each conversion specification has the following format:</p>
</li>
</ul>

<dl>
<dd><ul>
<li>
<p>introductory</p>

<code>%</code>

<p>character.</p>
</li>
</ul></dd>
</dl>

<dl>
<dd><ul>
<li>
<span class="mark-note">(optional)</span>

<p>assignment-suppressing character</p>

<code>*</code>

<p>. If this option is present, the function does not assign the result of the conversion to any receiving argument.</p>
</li>
</ul></dd>
</dl>

<dl>
<dd><ul>
<li>
<span class="mark-note">(optional)</span>

<p>integer number (greater than zero) that specifies</p>

<em>maximum field width</em>

<p>, that is, the maximum number of characters that the function is allowed to consume when doing the conversion specified by the current conversion specification. Note that</p>

<code>%s</code>

<p>and</p>

<code>%[</code>

<p>may lead to buffer overflow if the width is not provided.</p>
</li>
</ul></dd>
</dl>

<dl>
<dd><ul>
<li>
<span class="mark-note">(optional)</span>

<em>length modifier</em>

<p>that specifies the size of the receiving argument, that is, the actual destination type. This affects the conversion accuracy and overflow rules. The default destination type is different for each conversion type (see table below).</p>
</li>
</ul></dd>
</dl>

<dd><ul>
<li>
<p>conversion format specifier.</p>
</li>
</ul></dd>
</dl>

<p>For every conversion specifier other than <code>n</code>, the longest sequence of input characters which does not exceed any specified ﬁeld width and which either is exactly what the conversion specifier expects or is a prefix of a sequence it would expect, is what's consumed from the stream. The ﬁrst character, if any, after this consumed sequence remains unread. If the consumed sequence has length zero or if the consumed sequence cannot be converted as specified above, the matching failure occurs unless end-of-ﬁle, an encoding error, or a read error prevented input from the stream, in which case it is an input failure.</p>

<p>All conversion specifiers other than <code>[</code>, <code>c</code>, and <code>n</code> consume and discard all leading whitespace characters (determined as if by calling <a href="/reference/c/string/byte/isspace/"><code>isspace</code></a>) before attempting to parse the input. These consumed characters do not count towards the specified maximum field width.</p>

<p>The conversion specifiers <code>lc</code>, <code>ls</code>, and <code>l[</code> perform multibyte-to-wide character conversion as if by calling <a href="/reference/c/string/multibyte/mbrtowc/"><code>mbrtowc</code></a> with an <a href="/reference/c/string/multibyte/mbstate_t/"><code>mbstate_t</code></a> object initialized to zero before the first character is converted.</p>

<p>The conversion specifiers <code>s</code> and <code>[</code> always store the null terminator in addition to the matched characters. The size of the destination array must be at least one greater than the specified field width. The use of <code>%s</code> or <code>%[</code>, without specifying the destination array size, is as unsafe as <a href="/reference/c/io/gets/">gets</a>.</p>

<p>The correct conversion specifications for the <a href="/reference/c/types/integer/">fixed-width integer types</a> (<a href="/reference/c/types/integer/">int8_t</a>, etc) are defined in the header <a href="/reference/c/types/integer/"><code>&lt;inttypes.h&gt;</code></a> (although <a href="/reference/c/types/integer/"><code>SCNdMAX</code></a>, <a href="/reference/c/types/integer/"><code>SCNuMAX</code></a>, etc is synonymous with <code>%jd</code>, <code>%ju</code>, etc).</p>

<p>There is a <a href="/reference/c/language/eval_order/">sequence point</a> after the action of each conversion specifier; this permits storing multiple fields in the same "sink" variable.</p>

<p>When parsing an incomplete floating-point value that ends in the exponent with no digits, such as parsing <code>&quot;100er&quot;</code> with the conversion specifier <code>%f</code>, the sequence <code>&quot;100e&quot;</code> (the longest prefix of a possibly valid floating-point number) is consumed, resulting in a matching error (the consumed sequence cannot be converted to a floating-point number), with <code>&quot;r&quot;</code> remaining. Some existing implementations do not follow this rule and roll back to consume only <code>&quot;100&quot;</code>, leaving <code>&quot;er&quot;</code>, e.g. <a href="https://sourceware.org/bugzilla/show_bug.cgi?id=1765" rel="noreferrer" target="_blank">glibc bug 1765</a>.</p>

<p>A conversion specification must be valid. Otherwise, the behavior is undefined.</p>

<p>If a conversion specification is invalid, the behavior is undefined.</p>

<h3 id="Return_value">Return value</h3>

<p class="li-note"><span class="li-num">1-3)</span>  Number of receiving arguments successfully assigned (which may be zero in case a matching failure occurred before the first receiving argument was assigned), or <a href="/reference/c/io/">EOF</a> if input failure occurs before the first receiving argument was assigned.</p>

<p class="li-note"><span class="li-num">4-6)</span>  Same as (1-3), except that <a href="/reference/c/io/">EOF</a> is also returned if there is a runtime constraint violation.</p>

<h3 id="Complexity">Complexity</h3>

<p>Not guaranteed. Notably, some implementations of <code>sscanf</code> are O(N), where <code>N = strlen(buffer)</code> <a href="https://sourceware.org/bugzilla/show_bug.cgi?id=17577" rel="noreferrer" target="_blank">[1]</a>.</p>

<h3 id="Notes">Notes</h3>

<p>Because most conversion specifiers first consume all consecutive whitespace, code such as</p>

```c
scanf("%d", &a);
scanf("%d", &b);
```

<p>will read two integers that are entered on different lines (second <code>%d</code> will consume the newline left over by the first) or on the same line, separated by spaces or tabs (second <code>%d</code> will consume the spaces or tabs).</p>

<p>The conversion specifiers that do not consume leading whitespace, such as</p>

<code>%c</code>

<p>, can be made to do so by using a whitespace character in the format string:</p>

```c
scanf("%d", &a);
scanf(" %c", &c); // consume all consecutive whitespace after %d, then read a char
```

<h3 id="Example">Example</h3>

```c
#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
#include <stddef.h>
#include <locale.h>
 
int main(void)
{
    int i, j;
    float x, y;
    char str1[10], str2[4];
    wchar_t warr[2];
    setlocale(LC_ALL, "en_US.utf8");
 
    char input[] = "25 54.32E-1 Thompson 56789 0123 56ß水";
    /* parse as follows:
       %d: an integer
       %f: a floating-point value
       %9s: a string of at most 9 non-whitespace characters
       %2d: two-digit integer (digits 5 and 6)
       %f:  a floating-point value (digits 7, 8, 9)
       %*d: an integer which isn't stored anywhere
       ' ': all consecutive whitespace
       %3[0-9]: a string of at most 3 decimal digits (digits 5 and 6)
       %2lc: two wide characters, using multibyte to wide conversion  */
    int ret = sscanf(input, "%d%f%9s%2d%f%*d %3[0-9]%2lc",
                     &i, &x, str1, &j, &y, str2, warr);
 
    printf("Converted %d fields:\n"
           "i = %d\n"
           "x = %f\n"
           "str1 = %s\n"
           "j = %d\n"
           "y = %f\n"
           "str2 = %s\n"
           "warr[0] = U+%x\n"
           "warr[1] = U+%x\n",
           ret, i, x, str1, j, y, str2, warr[0], warr[1]);
 
#ifdef __STDC_LIB_EXT1__
    int n = sscanf_s(input, "%d%f%s", &i, &x, str1, (rsize_t)sizeof str1);
    // writes 25 to i, 5.432 to x, the 9 bytes "Thompson\0" to str1, and 3 to n.
#endif
}
```

<p>Possible output:</p>

```text
Converted 7 fields:
i = 25
x = 5.432000
str1 = Thompson
j = 56
y = 789.000000
str2 = 56
warr[0] = U+df
warr[1] = U+6c34
```
