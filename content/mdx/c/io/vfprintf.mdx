<p class="decl-note">(8) <span class="std std-since std-c11">(since C11)</span></p>

<p>Loads the data from the locations, defined by <code>vlist</code>, converts them to character string equivalents and writes the results to a variety of sinks.</p>

<p class="li-note"><span class="li-num">1)</span>  Writes the results to <a href="/reference/c/io/std_streams/">stdout</a>.</p>

<p class="li-note"><span class="li-num">2)</span>  Writes the results to a file stream <code>stream</code>.</p>

<p class="li-note"><span class="li-num">3)</span>  Writes the results to a character string <code>buffer</code>.</p>

<p class="li-note"><span class="li-num">4)</span>  Writes the results to a character string <code>buffer</code>. At most <code>bufsz - 1</code> characters are written. The resulting character string will be terminated with a null character, unless <code>bufsz</code> is zero. If <code>bufsz</code> is zero, nothing is written and <code>buffer</code> may be a null pointer, however the return value (number of bytes that would be written not including the null terminator) is still calculated and returned.</p>

<p>The floating-point conversion functions convert infinity to <code>inf</code> or <code>infinity</code>. Which one is used is implementation defined.</p>

<p>Not-a-number is converted to <code>nan</code> or <code>nan(char_sequence)</code>. Which one is used is implementation defined.</p>

<p>The conversions <code>F</code>, <code>E</code>, <code>G</code>, <code>A</code> output <code>INF</code>, <code>INFINITY</code>, <code>NAN</code> instead.</p>

<p>The conversion specifier used to print <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code> expects promoted types of <a href="/reference/c/language/conversion/#Default_argument_promotions">default argument promotions</a>, but before printing its value will be converted to <code>char</code>, <code>unsigned char</code>, <code>signed char</code>, <code>short</code>, and <code>unsigned short</code>. It is safe to pass values of these types because of the promotion that takes place when a variadic function is called.</p>

<p>The correct conversion specifications for the fixed-width character types (<a href="/reference/c/types/integer/">int8_t</a>, etc) are defined in the header <a href="/reference/c/types/integer/"><code>&lt;inttypes.h&gt;</code></a> (although <a href="/reference/c/types/integer/">PRIdMAX</a>, <a href="/reference/c/types/integer/">PRIuMAX</a>, etc is synonymous with <code>%jd</code>, <code>%ju</code>, etc).</p>

<p>The memory-writing conversion specifier <code>%n</code> is a common target of security exploits where format strings depend on user input and is not supported by the bounds-checked <code>printf_s</code> family of functions.</p>

<p>There is a <a href="/reference/c/language/eval_order/">sequence point</a> after the action of each conversion specifier; this permits storing multiple <code>%n</code> results in the same variable or, as an edge case, printing a string modified by an earlier <code>%n</code> within the same call.</p>

<p>If a conversion specification is invalid, the behavior is undefined.</p>

<h3 id="Return_value">Return value</h3>

<p class="li-note"><span class="li-num">1-3)</span>  The number of characters written if successful or negative value if an error occurred.</p>

<p class="li-note"><span class="li-num">4)</span>  The number of characters written if successful or negative value if an error occurred. If the resulting string gets truncated due to <code>buf_size</code> limit, function returns the total number of characters (not including the terminating null-byte) which would have been written, if the limit was not imposed.</p>

<p class="li-note"><span class="li-num">5,6)</span>  number of characters transmitted to the output stream or negative value if an output error, a runtime constrants violation error, or an encoding error occurred.</p>

<p class="li-note"><span class="li-num">7)</span>  number of characters written to <code>buffer</code>, not counting the null character (which is always written as long as <code>buffer</code> is not a null pointer and <code>bufsz</code> is not zero and not greater than RSIZE_MAX), or zero on runtime constraint violations, and negative value on encoding errors</p>

<p class="li-note"><span class="li-num">8)</span>  number of characters not including the terminating null character (which is always written as long as <code>buffer</code> is not a null pointer and <code>bufsz</code> is not zero and not greater than RSIZE_MAX), which would have been written to <code>buffer</code> if <code>bufsz</code> was ignored, or a negative value if a runtime constraints violation or an encoding error occurred</p>

<h3 id="Notes">Notes</h3>

<p>All these functions invoke va_arg at least once, the value of <code>arg</code> is indeterminate after the return. These functions do not invoke va_end, and it must be done by the caller.</p>

<p><code>vsnprintf_s</code>, unlike <code>vsprintf_s</code>, will truncate the result to fit within the array pointed to by <code>buffer</code>.</p>

<p>The implementation of <code>vsnprintf_s</code> in the <a href="https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/vsnprintf-s-vsnprintf-s-vsnprintf-s-l-vsnwprintf-s-vsnwprintf-s-l" rel="noreferrer" target="_blank">Microsoft CRT</a> does not conform to the C standard. Microsoft's version has an extra parameter <code>size_t count</code> in third position that contains the maximum amount of characters to be written, not including the null terminator. This parameter is possibly distinct from the buffer size provided via the parameter <code>size_t bufsz</code>.</p>

<h3 id="Example">Example</h3>

```c
#include <stdarg.h>
#include <stdio.h>
#include <time.h>
 
void debug_log(const char* fmt, ...)
{
    struct timespec ts;
    timespec_get(&ts, TIME_UTC);
    char time_buf[100];
    size_t rc = strftime(time_buf, sizeof time_buf, "%D %T", gmtime(&ts.tv_sec));
    snprintf(time_buf + rc, sizeof time_buf - rc, ".%06ld UTC", ts.tv_nsec / 1000);
 
    va_list args1;
    va_start(args1, fmt);
    va_list args2;
    va_copy(args2, args1);
    char buf[1+vsnprintf(NULL, 0, fmt, args1)];
    va_end(args1);
    vsnprintf(buf, sizeof buf, fmt, args2);
    va_end(args2);
 
    printf("%s [debug]: %s\n", time_buf, buf);
}
 
int main(void)
{
    debug_log("Logging, %d, %d, %d", 1, 2, 3);
}
```

<p>Possible output:</p>

```text
02/20/15 21:58:09.072683 UTC [debug]: Logging, 1, 2, 3
```
