<p class="decl-header">Defined in header <code>&lt;stdio.h&gt;</code></p>

```c
char* gets( char* str );
```

<p class="decl-note">(1) <span class="std std-until std-c11">(removed in C11)</span></p>

```c
char* gets_s( char* str, rsize_t n );
```

<p class="decl-note">(2) <span class="std std-since std-c11">(since C11)</span></p>

<p class="li-note"><span class="li-num">1)</span>  Reads <a href="/reference/c/io/std_streams/">stdin</a> into the character array pointed to by <code>str</code> until a newline character is found or end-of-file occurs. A null character is written immediately after the last character read into the array. The newline character is discarded but not stored in the buffer.</p>

<p class="li-note"><span class="li-num">2)</span>  Reads characters from <a href="/reference/c/io/std_streams/">stdin</a> until a newline is found or end-of-file occurs. Writes only at most <code>n - 1</code> characters into the array pointed to by <code>str</code>, and always writes the terminating null character (unless <code>str</code> is a null pointer). The newline character, if found, is discarded and does not count toward the number of characters written to the buffer.</p>

<div class="li-note"><p>The following errors are detected at runtime and call the currently installed</p>

<a href="/reference/c/error/set_constraint_handler_s/">constraint handler</a>

<p>function:</p>

<ul>
<li>
<code>n</code>

<p>is zero;</p>
</li>
<li>
<code>n</code>

<p>is greater than</p>

<code>RSIZE_MAX</code>

<p>;</p>
</li>
<li>
<code>str</code>

<p>is a null pointer;</p>
</li>
<li>
<em>endline</em>

<p>or</p>

<em>eof</em>

<p>not encountered after storing</p>

<code>n - 1</code>

<p>characters to the buffer.</p>
</li>
</ul></div>

<p class="li-note">In any case, <code>gets_s</code> first finishes reading and discarding the characters from <a href="/reference/c/io/std_streams/">stdin</a> until new-line character, end-of-file condition, or read error before calling the constraint handler.</p>

<p class="li-note">As with all bounds-checked functions, <code>gets_s</code> is only guaranteed to be available if <code>__STDC_LIB_EXT1__</code> is defined by the implementation and if the user defines <code>__STDC_WANT_LIB_EXT1__</code> to the integer constant <code>1</code> before including <a href="/reference/c/io/"><code>&lt;stdio.h&gt;</code></a>.</p>

<h3 id="Parameters">Parameters</h3>

<table class="ref-table ref-params">
<tr><td>str</td><td>-</td><td>a character array the characters from <a href="/reference/c/io/std_streams/">stdin</a> to be written to</td></tr>
<tr><td>n</td><td>-</td><td>maximum number of characters that can be written to the array pointed to by <code>str</code></td></tr>
</table>

<h3 id="Return_value">Return value</h3>

<p><code>str</code> on success, a null pointer on failure.</p>

<p>If the failure has been caused by end of file condition, additionally sets the <em>eof</em> indicator (see <a href="/reference/c/io/feof/">feof()</a>) on <a href="/reference/c/io/std_streams/">stdin</a>. If the failure has been caused by some other error, sets the <em>error</em> indicator (see <a href="/reference/c/io/ferror/">ferror()</a>) on <a href="/reference/c/io/std_streams/">stdin</a>.</p>

<h3 id="Notes">Notes</h3>

<p>The <code>gets()</code> function does not perform bounds checking, therefore this function is extremely vulnerable to buffer-overflow attacks. It cannot be used safely (unless the program runs in an environment which restricts what can appear on <code>stdin</code>). For this reason, the function has been deprecated in the third corrigendum to the C99 standard and removed altogether in the C11 standard. <a href="/reference/c/io/fgets/">fgets()</a> and <code>gets_s()</code> are the recommended replacements.</p>

<p><strong>WARNING: Never use <code>gets()</code></strong>.</p>
