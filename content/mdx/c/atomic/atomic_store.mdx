<p class="decl-header">Defined in header <code>&lt;stdatomic.h&gt;</code></p>

```c
void atomic_store( volatile A* obj , C desired );
```

<p class="decl-note">(1) <span class="std std-since std-c11">(since C11)</span></p>

```c
void atomic_store_explicit( volatile A* obj, C desired, memory_order order );
```

<p class="decl-note">(2) <span class="std std-since std-c11">(since C11)</span></p>

<p>Atomically replaces the value of the atomic variable pointed to by <code>obj</code> with <code>desired</code>. The operation is atomic write operation.</p>

<p>The first version orders memory accesses according to <a href="/reference/c/atomic/memory_order/">memory_order_seq_cst</a>, the second version orders memory accesses according to <code>order</code>. <code>order</code> must be one of <a href="/reference/c/atomic/memory_order/">memory_order_relaxed</a>, <a href="/reference/c/atomic/memory_order/">memory_order_release</a> or <a href="/reference/c/atomic/memory_order/">memory_order_seq_cst</a>. Otherwise the behavior is undefined.</p>

<p>This is a <a href="/reference/c/language/generic/">generic function</a> defined for all <a href="/reference/c/language/atomic/">atomic object types</a> <code>A</code>. The argument is pointer to a volatile atomic type to accept addresses of both non-volatile and <a href="/reference/c/language/volatile/">volatile</a> (e.g. memory-mapped I/O) atomic objects, and volatile semantic is preserved when applying this operation to volatile atomic objects. <code>C</code> is the non-atomic type corresponding to <code>A</code>.</p>

<p>It is unspecified whether the name of a generic function is a macro or an identifier declared with external linkage. If a macro definition is suppressed in order to access an actual function (e.g. parenthesized like <code>(atomic_store)(...)</code>), or a program defines an external identifier with the name of a generic function, the behavior is undefined.</p>
