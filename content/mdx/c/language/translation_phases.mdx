<p>The C source file is processed by the compiler <em>as if</em> the following phases take place, in this exact order. Actual implementation may combine these actions or process them differently as long as the behavior is the same.</p>

<h3 id="Phase_1">Phase 1</h3>

<div class="li-note"><span class="li-num">1)</span>

<p>The individual bytes of the source code file (which is generally a text file in some multibyte encoding such as UTF-8) are mapped, in implementation defined manner, to the characters of the</p>

<em>source character set</em>

<p>. In particular, OS-dependent end-of-line indicators are replaced by newline characters.</p>

<dl>
<dd><p>The</p>

<em>source character set</em>

<p>is a multibyte character set which includes the</p>

<em>basic source character set</em>

<p>as a single-byte subset, consisting of the following 96 characters:</p></dd>
</dl></div>

<span class="li-num">a)</span>

<p>5 whitespace characters (space, horizontal tab, vertical tab, form feed, new-line)</p>

<span class="li-num">b)</span>

<p>10 digit characters from</p>

<code>&#x27;0&#x27;</code>

<p>to</p>

<code>&#x27;9&#x27;</code>

<span class="li-num">c)</span>

<p>52 letters from</p>

<code>&#x27;a&#x27;</code>

<p>to</p>

<code>&#x27;z&#x27;</code>

<p>and from</p>

<code>&#x27;A&#x27;</code>

<p>to</p>

<code>&#x27;Z&#x27;</code>

<span class="li-num">d)</span>

<p>29 punctuation characters:</p>

<code>_ { } [ ] # ( ) &lt; &gt; % : ; . ? * + - / ^ &amp; | ~ ! = , \ &quot; &#x27;</code>

<p class="li-note"><span class="li-num">2)</span>  <a href="/reference/c/language/operator_alternative/">Trigraph sequences</a> are replaced by corresponding single-character representations.<span class="std std-until std-c23">(until C23)</span></p>

<h3 id="Phase_2">Phase 2</h3>

<div class="li-note"><span class="li-num">1)</span>

<p>Whenever backslash appears at the end of a line (immediately followed by the newline character), both backslash and newline are deleted, combining two physical source lines into one logical source line. This is a single-pass operation: a line ending in two backslashes followed by an empty line does not combine three lines into one.</p>

```c
#include <stdio.h>
 
#define PUTS p\
u\
t\
s
/* Line splicing is in phase 2 while macros
 * are tokenized in phase 3 and expanded in phase 4,
 * so the above is equivalent to #define PUTS puts
 */
 
int main(void)
{
 /* Use line splicing to call puts */ PUT\
S\
("Output ends here\\
0Not printed" /* After line splicing, the remaining backslash
               * escapes the 0, ending the string early.
               */
);
}
```</div>

<p class="li-note"><span class="li-num">2)</span>  If a non-empty source file does not end with a newline character after this step (whether it had no newline originally, or it ended with a backslash), the behavior is undefined.</p>

<h3 id="Phase_3">Phase 3</h3>

<p class="li-note"><span class="li-num">1)</span>  The source file is decomposed into <a href="/reference/c/comment/">comment</a>, sequences of whitespace characters (space, horizontal tab, new-line, vertical tab, and form-feed), and <em>preprocessing tokens</em>, which are the following</p>

<span class="li-num">a)</span>

<p>header names:</p>

<code>&lt;stdio.h&gt;</code>

<p>or</p>

<code>&quot;myfile.h&quot;</code>

<span class="li-num">b)</span>

<a href="/reference/c/language/identifier/">identifiers</a>

<span class="li-num">c)</span>

<p>preprocessing numbers, which cover</p>

<a href="/reference/c/language/integer_constant/">integer constants</a>

<p>and</p>

<a href="/reference/c/language/floating_constant/">floating constants</a>

<p>, but also cover some invalid tokens such as</p>

<code>1..E+3.foo</code>

<p>or</p>

<code>0JBK</code>

<span class="li-num">d)</span>

<a href="/reference/c/language/character_constant/">character constants</a>

<p>and</p>

<a href="/reference/c/language/string_literal/">string literals</a>

<span class="li-num">e)</span>

<p>operators and punctuators, such as</p>

<code>+</code>

<p>,</p>

<code>&lt;&lt;=</code>

<p>,</p>

<code>&lt;%</code>

<p>, or</p>

<code>##</code>

<p>.</p>

<span class="li-num">f)</span>

<p>individual non-whitespace characters that do not fit in any other category</p>

<p class="li-note"><span class="li-num">2)</span>  Each comment is replaced by one space character</p>

<p class="li-note"><span class="li-num">3)</span>  Newlines are kept, and it's implementation-defined whether non-newline whitespace sequences may be collapsed into single space characters.</p>

<p>If the input has been parsed into preprocessing tokens up to a given character, the next preprocessing token is generally taken to be the longest sequence of characters that could constitute a preprocessing token, even if that would cause subsequent analysis to fail. This is commonly known as <em>maximal munch</em>.</p>

```c
int foo = 1;
// int bar = 0xE+foo; // error: invalid preprocessing number 0xE+foo
int bar = 0xE/*Comment expands to a space*/+foo; // OK: 0xE + foo
int baz = 0xE + foo; // OK: 0xE + foo
int pub = bar+++baz; // OK: bar++ + baz
int ham = bar++-++baz; // OK: bar++ - ++baz
// int qux = bar+++++baz; // error: bar++ ++ +baz, not bar++ + ++baz
int qux = bar+++/*Saving comment*/++baz; // OK: bar++ + ++baz
```

<p>The sole exception to the maximal munch rule is:</p>

<ul>
<li>
<p>Header name preprocessing tokens are only formed within a</p>

<a href="/reference/c/preprocessor/include/"><code>#include</code></a>

or <a href="/reference/c/preprocessor/embed/"><code>#embed</code></a><span class="std std-since std-c23">(since C23)</span>

<p>directive,</p>

in <a href="/reference/c/preprocessor/include/"><code>__has_include</code></a> and <a href="/reference/c/preprocessor/embed/"><code>__has_embed</code></a> expressions<span class="std std-since std-c23">(since C23)</span>

<p>and in implementation-defined locations within a</p>

<a href="/reference/c/preprocessor/impl/"><code>#pragma</code></a>

<p>directive.</p>
</li>
</ul>

```c
#define MACRO_1 1
#define MACRO_2 2
#define MACRO_3 3
#define MACRO_EXPR (MACRO_1 <MACRO_2> MACRO_3) // OK: <MACRO_2> is not a header-name
```

<h3 id="Phase_4">Phase 4</h3>

<p class="li-note"><span class="li-num">1)</span>  <a href="/reference/c/preprocessor/">Preprocessor</a> is executed.</p>

<p class="li-note"><span class="li-num">2)</span>  Each file introduced with the <a href="/reference/c/preprocessor/include/">#include</a> directive goes through phases 1 through 4, recursively.</p>

<p class="li-note"><span class="li-num">3)</span>  At the end of this phase, all preprocessor directives are removed from the source.</p>

<h3 id="Phase_5">Phase 5</h3>

<p class="li-note"><span class="li-num">1)</span>  All characters and <a href="/reference/c/language/escape/">escape sequences</a> in <a href="/reference/c/language/character_constant/">character constants</a> and <a href="/reference/c/language/string_literal/">string literals</a> are converted from <em>source character set</em> to <em>execution character set</em> (which may be a multibyte character set such as UTF-8, as long as all 96 characters from the <em>basic source character set</em> listed in phase 1 have single-byte representations). If the character specified by an escape sequence isn't a member of the execution character set, the result is implementation-defined, but is guaranteed to not be a null (wide) character.</p>

<p>Note: the conversion performed at this stage can be controlled by command line options in some implementations: gcc and clang use <code>-finput-charset</code> to specify the encoding of the source character set, <code>-fexec-charset</code> and <code>-fwide-exec-charset</code> to specify the encodings of the execution character set in the string literals and character constants that don't have an encoding prefix<span class="std std-since std-c11">(since C11)</span>.</p>

<h3 id="Phase_6">Phase 6</h3>

<p>Adjacent <a href="/reference/c/language/string_literal/">string literals</a> are concatenated.</p>

<h3 id="Phase_7">Phase 7</h3>

<p>Compilation takes place: the tokens are syntactically and semantically analyzed and translated as a translation unit.</p>

<h3 id="Phase_8">Phase 8</h3>

<p>Linking takes place: Translation units and library components needed to satisfy external references are collected into a program image which contains information needed for execution in its execution environment (the OS).</p>
