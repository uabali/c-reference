<p>Each individual type in the C <a href="/reference/c/language/compatible_type/">type system</a> has several <em>qualified</em> versions of that type, corresponding to one, two, or all three of the <code>const</code>, <a href="/reference/c/language/volatile/"><code>volatile</code></a>, and, for pointers to object types, <a href="/reference/c/language/restrict/"><code>restrict</code></a> qualifiers. This page describes the effects of the <code>const</code> qualifier.</p>

<p>Objects <a href="/reference/c/language/declarations/">declared</a> with const-qualified types may be placed in read-only memory by the compiler, and if the address of a const object is never taken in a program, it may not be stored at all.</p>

<p>Any attempt to modify an object whose type is const-qualified results in undefined behavior.</p>

```c
const int n = 1; // object of const-qualified type
int* p = (int*)&n;
*p = 2; // undefined behavior
```

<p><code>const</code> semantics apply to <a href="/reference/c/language/value_category/">lvalue</a> expressions only; whenever a const lvalue expression is used in context that does not require an lvalue, its <code>const</code> qualifier is lost (note that volatile qualifier, if present, isn't lost).</p>

<p>The lvalue expressions that designate objects of const-qualified type and the lvalue expressions that designate objects of struct or union type with at least one member of const-qualified type (including members of recursively contained aggregates or unions), are not <em>modifiable lvalues</em>. In particular, they are not assignable:</p>

```c
const int n = 1; // object of const type
n = 2; // error: the type of n is const-qualified
 
int x = 2; // object of unqualified type
const int* p = &x;
*p = 3; // error: the type of the lvalue *p is const-qualified
 
struct {int a; const int b; } s1 = {.b=1}, s2 = {.b=2};
s1 = s2; // error: the type of s1 is unqualified, but it has a const member
```

<p>A member of a const-qualified structure or union type acquires the qualification of the type it belongs to (both when accessed using the <code>.</code> operator or the <code>-&gt;</code> operator).</p>

```c
struct s { int i; const int ci; } s;
// the type of s.i is int, the type of s.ci is const int
const struct s cs;
// the types of cs.i and cs.ci are both const int
```

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p>If an array type is declared with the const type qualifier (through the use of <a href="/reference/c/language/typedef/">typedef</a>), the array type is not const-qualified, but its element type is.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>An array type and its element type are always considered to be identically const-qualified.</p></aside>

```c
typedef int A[2][3];
const A a = {{4, 5, 6}, {7, 8, 9}}; // array of array of const int
int* pi = a[0]; // Error: a[0] has type const int*
void *unqual_ptr = a; // OK until C23; error since C23
// Notes: clang applies the rule in C++/C23 even in C89-C17 modes
```

<p>If a function type is declared with the const type qualifier (through the use of <a href="/reference/c/language/typedef/">typedef</a>), the behavior is undefined.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>In a function declaration, the keyword <code>const</code> may appear inside the square brackets that are used to declare an array type of a function parameter. It qualifies the pointer type to which the array type is transformed.</p>

<p>The following two declarations declare the same function:</p>

```c
void f(double x[const], const double y[const]);
void f(double * const x, const double * const y);
```</aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>const-qualified compound literals do not necessarily designate distinct objects; they may share storage with other compound literals and with string literals that happen to have the same or overlapping representation.</p>

```c
const int* p1 = (const int[]){1, 2, 3};
const int* p2 = (const int[]){2, 3, 4}; // the value of p2 may equal p1+1
_Bool b = "foobar" + 3 == (const char[]){"bar"}; // the value of b may be 1
```</aside>

<p>A pointer to a non-const type can be implicitly converted to a pointer to const-qualified version of the same or <a href="/reference/c/language/compatible_type/">compatible</a> type. The reverse conversion requires a cast expression.</p>

```c
int* p = 0;
const int* cp = p; // OK: adds qualifiers (int to const int)
p = cp; // Error: discards qualifiers (const int to int)
p = (int*)cp; // OK: cast
```

<p>Note that pointer to pointer to <code>T</code> is not convertible to pointer to pointer to <code>const T</code>; for two types to be compatible, their qualifications must be identical.</p>

```c
char *p = 0;
const char **cpp = &p; // Error: char* and const char* are not compatible types
char * const *pcp = &p; // OK, adds qualifiers (char* to char*const)
```

<h3 id="Keywords">Keywords</h3>

<p><a href="https://en.cppreference.com/w/cpp/keyword/const" rel="noreferrer" target="_blank"><code>const</code></a></p>

<h3 id="Notes">Notes</h3>

<p>C adopted the <em>const</em> qualifier from C++, but unlike in C++, expressions of const-qualified type in C are not <a href="/reference/c/language/constant_expression/">constant expressions</a>; they may not be used as <a href="/reference/c/language/switch/">case</a> labels or to initialize <a href="/reference/c/language/static_storage_duration/">static</a> and <a href="/reference/c/language/thread_storage_duration/">thread</a> storage duration objects, <a href="/reference/c/language/enum/">enumerators</a>, or <a href="/reference/c/language/bit_field/">bit-field</a> sizes. When they are used as <a href="/reference/c/language/array/">array</a> sizes, the resulting arrays are VLAs.</p>
