<p>Allows values of floating type to be used directly in expressions.</p>

<h3 id="Syntax">Syntax</h3>

<p>A floating constant is a <a href="/reference/c/language/value_category/">non-lvalue</a> expression having the form:</p>

```text
significand exponent (optional) suffix (optional)
```

<p>Where the <em>significand</em> has the form</p>

```text
whole-number (optional) .(optional) fraction (optional)
```

<p>The <em>exponent</em> has the form</p>

```text
e | E exponent-sign (optional) digit-sequence
p | P exponent-sign (optional) digit-sequence
```

<p class="li-note"><span class="li-num">1)</span>  The exponent syntax for a decimal floating-point constant</p>

<p class="li-note"><span class="li-num">2)</span>  The exponent syntax for hexadecimal floating-point constant</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Optional single quotes (<code>&#x27;</code>) can be inserted between the digits as a separator, they are ignored when compiling.</p></aside>

<h3 id="Explanation">Explanation</h3>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>If the <em>significand</em> begins with the character sequence <code>0x</code> or <code>0X</code>, the floating constant is a <em>hexadecimal floating constant</em>. Otherwise, it is a <em>decimal floating constant</em>.</p>

<p>For a <em>hexadecimal floating constant</em>, the <em>significand</em> is interpreted as a hexadecimal rational number, and the <em>digit-sequence</em> of the exponent is interpreted as the integer power of 2 to which the significand has to be scaled.</p>

```c
double d = 0x1.2p3; // hex fraction 1.2 (decimal 1.125) scaled by 2^3, that is 9.0
```</aside>

<p>For a <em>decimal floating constant</em>, the <em>significand</em> is interpreted as a decimal rational number, and the <em>digit-sequence</em> of the exponent is interpreted as the integer power of 10 to which the significand has to be scaled.</p>

```c
double d = 1.2e3; // decimal fraction 1.2 scaled by 10^3, that is 1200.0
```

<h4 id="Suffixes">Suffixes</h4>

<p>An unsuffixed floating constant has type <code>double</code>. If <em>suffix</em> is the letter <code>f</code> or <code>F</code>, the floating constant has type <code>float</code>. If <em>suffix</em> is the letter <code>l</code> or <code>L</code>, the floating constant has type <code>long double</code>.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>If the implementation predefines macro <code>__STDC_IEC_60559_BFP__</code>, the following suffixes and corresponding floating constants are additionally supported:</p>

<ul>
<li>
<p>if</p>

<em>suffix</em>

<p>is</p>

<code>df</code>

<p>or</p>

<code>DF</code>

<p>, the floating constant has type</p>

<code>_Decimal32</code>

<p>;</p>
</li>
<li>
<p>if</p>

<em>suffix</em>

<p>is</p>

<code>dd</code>

<p>or</p>

<code>DD</code>

<p>, the floating constant has type</p>

<code>_Decimal64</code>

<p>;</p>
</li>
<li>
<p>if</p>

<em>suffix</em>

<p>is</p>

<code>dl</code>

<p>or</p>

<code>DL</code>

<p>, the floating constant has type</p>

<code>_Decimal128</code>

<p>.</p>
</li>
</ul>

<p>Suffixes for decimal floating-point types are not allowed in hexadecimal floating constants.</p></aside>

<h4 id="Optional_parts">Optional parts</h4>

<p>If the exponent is present and fractional part is not used, the decimal separator may be omitted:</p>

```c
double x = 1e0; // floating-point 1.0 (period not used)
```

<p>For decimal floating constants, the <em>exponent</em> part is optional. If it is omitted, the period is not optional, and either the <em>whole-number</em> or the <em>fraction</em> must be present.</p>

```c
double x = 1.; // floating-point 1.0 (fractional part optional)
double y = .1; // floating-point 0.1 (whole-number part optional)
```

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>For hexadecimal floating constants, the exponent is not optional to avoid ambiguity resulting from an <code>f</code> suffix being mistaken as a hexadecimal digit.</p></aside>

<h4 id="Representable_values">Representable values</h4>

<p>The result of evaluating a floating constant is either the nearest representable value or the larger or smaller representable value immediately adjacent to the nearest representable value, chosen in an implementation-defined manner (in other words, <a href="/reference/c/numeric/fenv/FE_round/">default rounding direction</a> during translation is implementation-defined).</p>

<p>All floating constants of the same source form convert to the same internal format with the same value. Floating constants of different source forms, e.g. <code>1.23</code> and <code>1.230</code>, need not to convert to the same internal format and value.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>Floating-point constants may convert to more range and precision than is indicated by their type, if indicated by <a href="/reference/c/types/limits/FLT_EVAL_METHOD/">FLT_EVAL_METHOD</a>. For example, the constant <code>0.1f</code> may act as if it were <code>0.1L</code> in an expression.</p>

<p>The result of evaluating a hexadecimal floating constant, if <a href="/reference/c/types/limits/">FLT_RADIX</a> is 2, is the exact value represented by the floating constant, correctly rounded to the target type.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Floating constants of decimal floating-point type that have the same numerical value \(\small x\)x but different quantum exponents, e.g. <code>1230.dd</code>, <code>1230.0dd</code>, and <code>1.23e3dd</code>, have distinguishable internal representations.</p>

<p>The quantum exponent \(\small q\)q of a floating constant of a decimal floating-point type is determined in the manner that \(\small 10^q\)10q  represents 1 at the place of last digit of the <em>significand</em> when possible. If the quantum exponent \(\small q\)q and the coefficient \(\small c = x\cdot 10^{-q}\)c=x·10-q  determined above cannot represented exactly in the type of the floating constant, \(\small q\)q is increased as needed within the limit of the type, and \(\small c\)c is reduced correspondingly, with needed rounding. The rounding may result in zero or infinity. If (the possibly rounded) \(\small c\)c is still out of the permitted range after \(\small q\)q reaches the maximum value, the resulted floating constant has value positive infinity.</p></aside>

<h3 id="Notes">Notes</h3>

<p>Default <a href="/reference/c/numeric/fenv/FE_round/">rounding direction</a> and <a href="/reference/c/types/limits/FLT_EVAL_METHOD/">precision</a> are in effect when the floating constants are converted into internal representations, and <a href="/reference/c/numeric/fenv/FE_exceptions/">floating-point exceptions</a> are not raised even if <a href="/reference/c/preprocessor/impl/"><code>#pragma STDC FENV_ACCESS</code></a> is in effect (for execution-time conversion of character strings, <a href="/reference/c/string/byte/strtof/">strtod</a> can be used). Note that this differs from <a href="/reference/c/language/constant_expression/">arithmetic constant expressions</a> of floating type.</p>

<p>Letters in the floating constants are case-insensitive, except that uppercase and lowercase cannot be both used in suffixes for decimal floating-point types<span class="std std-since std-c23">(since C23)</span>: <code>0x1.ep+3</code> and <code>0X1.EP+3</code> represent the same floating-point value <code>15.0</code>.</p>

<p>The decimal point specified by <a href="/reference/c/locale/setlocale/">setlocale</a> has no effect on the syntax of floating constants: the decimal point character is always the period.</p>

<p>Unlike integers, not every floating value can be represented directly by decimal or even hexadecimal<span class="std std-since std-c99">(since C99)</span> constant syntax: macros <a href="/reference/c/numeric/math/NAN/"><code>NAN</code></a> and <a href="/reference/c/numeric/math/INFINITY/"><code>INFINITY</code></a> as well as functions such as <a href="/reference/c/numeric/math/nan.2/">nan</a> offer ways to generate those special values<span class="std std-since std-c99">(since C99)</span>. Note that <code>0x1.FFFFFEp128f</code>, which might appear to be an IEEE float NaN, in fact overflows to an infinity in that format.</p>

<p>There are no negative floating constants; an expression such as <code>-1.2</code> is the <a href="/reference/c/language/operator_arithmetic/">arithmetic operator</a> unary minus applied to the floating constant <code>1.2</code>. Note that the special value negative zero may be constructed with <code>-0.0</code>.</p>

<h3 id="Example">Example</h3>

```c
#include <stdio.h>
 
int main(void)
{
    printf("15.0     = %a\n", 15.0);
    printf("0x1.ep+3 = %f\n", 0x1.ep+3);
 
    // Constants outside the range of type double.
    printf("+2.0e+308 --> %g\n",  2.0e+308);
    printf("+1.0e-324 --> %g\n",  1.0e-324);
    printf("-1.0e-324 --> %g\n", -1.0e-324);
    printf("-2.0e+308 --> %g\n", -2.0e+308);
}
```

<p>Output:</p>

```text
15.0     = 0x1.ep+3
0x1.ep+3 = 15.000000
+2.0e+308 --> inf
+1.0e-324 --> 0
-1.0e-324 --> -0
-2.0e+308 --> -inf
```
