<p>An <em>identifier</em> is an arbitrarily long sequence of digits, underscores, lowercase and uppercase Latin letters, and Unicode characters specified using <code>\u</code> and <code>\U</code> <a href="/reference/c/language/escape/">escape</a> notation<span class="std std-since std-c99">(since C99)</span>, of class <a href="https://www.unicode.org/reports/tr31/#Table_Lexical_Classes_for_Identifiers" rel="noreferrer" target="_blank">XID_Continue</a><span class="std std-since std-c23">(since C23)</span>. A valid identifier must begin with a non-digit character (Latin letter, underscore, or Unicode non-digit character<span class="std std-since std-c99">(since C99)</span><span class="std std-until std-c23">(until C23)</span>, or Unicode character of class <a href="https://www.unicode.org/reports/tr31/#Table_Lexical_Classes_for_Identifiers" rel="noreferrer" target="_blank">XID_Start</a>)<span class="std std-since std-c23">(since C23)</span>). Identifiers are case-sensitive (lowercase and uppercase letters are distinct). Every identifier must conform to <a href="https://www.unicode.org/charts/normalization/" rel="noreferrer" target="_blank">Normalization Form C</a>.<span class="std std-since std-c23">(since C23)</span></p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span> <span class="std std-until std-c23">(until C23)</span></p><p>It is implementation-defined if raw (not escaped) Unicode characters are allowed in identifiers:</p>

```c
char *\U0001f431 = "cat"; // supported
char *🐱 = "cat"; // implementation-defined
                  // (e.g. works with Clang, but not GCC prior to version 10)
                  // both are ill formed in C23. Emoji are not XID_Start characters
```</aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Implementation-defined characters whose corresponding code points in</p>

<a href="https://unicode.org/L2/L2010/10038-fcd10646-main.pdf" rel="noreferrer" target="_blank">ISO/IEC 10646</a>

<p>(Unicode) have the XID_Start or XID_Continue property can appear in the beginning or after the first character of an identifier respectively.</p></aside>

<p>Identifiers can denote the following types of entities:</p>

<ul>
<li>
<a href="/reference/c/language/object/">objects</a>
</li>
<li>
<a href="/reference/c/language/functions/">functions</a>
</li>
<li>
<p>tags (</p>

<a href="/reference/c/language/struct/">struct</a>

<p>,</p>

<a href="/reference/c/language/union/">union</a>

<p>, or</p>

<a href="/reference/c/language/enum/">enumerations</a>

<p>)</p>
</li>
<li>
<p>structure or union members</p>
</li>
<li>
<p>enumeration constants</p>
</li>
<li>
<a href="/reference/c/language/typedef/">typedef</a>

<p>names</p>
</li>
<li>
<a href="/reference/c/language/statements/#Labels">label</a>

<p>names</p>
</li>
<li>
<a href="/reference/c/preprocessor/replace/">macro</a>

<p>names</p>
</li>
<li>
<a href="/reference/c/preprocessor/replace/">macro parameter</a>

<p>names</p>
</li>
</ul>

<p>Every identifier other than macro names or macro parameter names has <a href="/reference/c/language/scope/">scope</a>, belongs to a <a href="/reference/c/language/name_space/">name space</a>, and may have <a href="/reference/c/language/storage_duration/">linkage</a>. The same identifier can denote different entities at different points in the program, or may denote different entities at the same point if the entities are in different name spaces.</p>

<h3 id="Reserved_identifiers">Reserved identifiers</h3>

<p>The following identifiers are <em>reserved</em> and may not be declared in a program (doing so invokes undefined behavior):</p>

<ol>
<li>
<p>The identifiers that are</p>

<a href="/reference/c/keyword/">keywords</a>

<p>cannot be used for other purposes. In particular #define or #undef of an identifier that is identical to a keyword is not allowed.</p>
</li>
<li>
<p>All external identifiers that begin with an underscore.</p>
</li>
<li>
<p>All identifiers that begin with an underscore followed by a capital letter or by another underscore (these reserved identifiers allow the library to use numerous behind-the-scenes non-external macros and functions).</p>
</li>
<li>
<p>All external identifiers defined by the standard library (in hosted environment). This means that no user-supplied external names are allowed to match any library names, not even if declaring a function that is identical to a library function.</p>
</li>
<li>
<p>Identifiers declared as reserved for the implementation or future use by the standard library (see below).</p>
</li>
<li>
Identifiers declared as potentially reserved and provided by the implementation (see below).

<span class="std std-since std-c23">(since C23)</span>
</li>
</ol>

<p>All other identifiers are available. Identifiers that are not reserved or potentially reserved<span class="std std-since std-c23">(since C23)</span> can be used with no fear of unexpected collisions when moving programs from one compiler and library to another.</p>

<p>Note: in C++, identifiers with a double underscore anywhere are reserved everywhere; in C, only the ones that begin with a double underscore are reserved.</p>

<h4 id="Reserved_and_potentially_reserved_identifiers_in_the_library">Reserved and potentially reserved identifiers in the library</h4>

<p>The standard library reserves every identifier it provides. Reserved identifiers that have <a href="/reference/c/language/storage_duration/">external linkage</a> (e.g. name of every standard function) are reserved regardless which header is included. Other reserved identifiers are reserved when any of its associated headers is included.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Potentially reserved identifiers are intended to be used by the implementation and future revision of standard. If a potentially reserved identifier is provided by the implementation, it becomes reserved.</p>

<p>Implementations are only allowed to provide <a href="/reference/c/language/extern/">external definitions</a> of potentially reserved identifiers that are reserved as function names.</p>

<p>Potentially reserved identifiers that are not provided by the implementation are not reserved. They can be declared or defined by the user without undefined behavior. However, such usage is not portable.</p></aside>

<h3 id="Translation_limits">Translation limits</h3>

<p>Even though there is no specific limit on the length of identifiers, early compilers had limits on the number of significant initial characters in identifiers and the linkers imposed stricter limits on the names with <a href="/reference/c/language/storage_duration/">external linkage</a>. C requires that at least the following limits are supported by any standard-compliant implementation:</p>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c99">(until C99)</span></p><ul>
<li>
<p>31 significant initial characters in an internal identifier or a macro name</p>
</li>
<li>
<p>6 significant initial characters in an external identifier</p>
</li>
<li>
<p>511 external identifiers in one translation unit</p>
</li>
<li>
<p>127 identifiers with block scope declared in one block</p>
</li>
<li>
<p>1024 macro identifiers simultaneously defined in one preprocessing translation unit</p>
</li>
</ul></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><ul>
<li>
<p>63 significant initial characters in an internal identifier or a macro name</p>
</li>
<li>
<p>31 significant initial characters in an external identifier</p>
</li>
<li>
<p>4095 external identifiers in one translation unit</p>
</li>
<li>
<p>511 identifiers with block scope declared in one block</p>
</li>
<li>
<p>4095 macro identifiers simultaneously defined in one preprocessing translation unit</p>
</li>
</ul></aside>
