<p>Constructs an unnamed object of specified character array type in-place, used when a character string needs to be embedded in source code.</p>

<h3 id="Syntax">Syntax</h3>

```text
" s-char-sequence "
u8" s-char-sequence "
u" s-char-sequence "
U" s-char-sequence "
L" s-char-sequence "
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>s-char-sequence</em></td><td>-</td><td>zero or more characters, each of which is either a multibyte character from the source character set (excluding (<code>&quot;</code>), <code>\</code>, and newline), or character escape, hex escape, octal escape, or universal character name<span class="std std-since std-c99">(since C99)</span> as defined in <a href="/reference/c/language/escape/">escape sequences</a>.</td></tr>
</table>

<p class="li-note"><span class="li-num">1)</span>  <em>character string literal</em>: The type of the literal is <code>char[N]</code>, where <code>N</code> is the size of the string in code units of the execution narrow encoding, including the null terminator. Each <code>char</code> element in the array is initialized from the next character in <em>s-char-sequence</em> using the execution character set.</p>

<p class="li-note"><span class="li-num">2)</span>  <em>UTF-8 string literal</em>: The type of the literal is <code>char[N]</code><span class="std std-until std-c23">(until C23)</span><code>char8_t[N]</code><span class="std std-since std-c23">(since C23)</span>, where <code>N</code> is the size of the string in UTF-8 code units including the null terminator. Each <code>char</code><span class="std std-until std-c23">(until C23)</span><code>char8_t</code><span class="std std-since std-c23">(since C23)</span> element in the array is initialized from the next multibyte character in <em>s-char-sequence</em> using UTF-8 encoding.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p class="li-note"><span class="li-num">3)</span>  16-bit wide string literal: The type of the literal is <code>char16_t[N]</code>, where <code>N</code> is the size of the string in code units of implementation-defined 16-bit encoding (typically UTF-16), including the null terminator. Each <code>char16_t</code> element in the array is initialized as if by executing <a href="/reference/c/string/multibyte/mbrtoc16/">mbrtoc16</a> in implementation-defined locale.</p>

<p class="li-note"><span class="li-num">4)</span>  32-bit wide string literal: The type of the literal is <code>char32_t[N]</code>, where <code>N</code> is the size of the string in code units of implementation-defined 32-bit encoding (typically UTF-32), including the null terminator. Each <code>char32_t</code> element in the array is initialized as if by executing <a href="/reference/c/string/multibyte/mbrtoc32/">mbrtoc32</a> in implementation-defined locale.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p class="li-note"><span class="li-num">3)</span>  <em>UTF-16 string literal</em>: The type of the literal is <code>char16_t[N]</code>, where <code>N</code> is the size of the string in UTF-16 code units including the null terminator. Each <code>char16_t</code> element in the array is initialized from the next multibyte character in <em>s-char-sequence</em> using UTF-16 encoding.</p>

<p class="li-note"><span class="li-num">4)</span>  <em>UTF-32 string literal</em>: The type of the literal is <code>char32_t[N]</code>, where <code>N</code> is the size of the string in UTF-32 code units including the null terminator. Each <code>char32_t</code> element in the array is initialized from the next multibyte character in <em>s-char-sequence</em> using UTF-32 encoding.</p></aside>

<p class="li-note"><span class="li-num">5)</span>  wide string literal: The type of the literal is <code>wchar_t[N]</code>, where <code>N</code> is the size of the string in code units of the execution wide encoding, including the null terminator. Each <code>wchar_t</code> element in the array is initialized as if by executing <a href="/reference/c/string/multibyte/mbstowcs/">mbstowcs</a> in implementation-defined locale.</p>

<h3 id="Explanation">Explanation</h3>

<p>First, at <a href="/reference/c/language/translation_phases/">translation phase 6</a> (after macro expansion), the adjacent string literals (that is, string literals separated by whitespace only) are concatenated.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c99">(until C99)</span></p><p>Only two narrow or two wide string literals may be concatenated.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>If one literal is unprefixed, the resulting string literal has the width/encoding specified by the prefixed literal.</p>

```c
L"Δx = %" PRId16 // at phase 4, PRId16 expands to "d"
                 // at phase 6, L"Δx = %" and "d" form L"Δx = %d"
```</aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span> <span class="std std-until std-c23">(until C23)</span></p><p>If the two string literals have different encoding prefixes, concatenation is implementation-defined, except that a UTF-8 string literal and a wide string literal cannot be concatenated.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>If the two string literals have different encoding prefixes, concatenation is ill-formed.</p></aside>

<p>Secondly, at <a href="/reference/c/language/translation_phases/">translation phase 7</a>, a terminating null character is added to each string literal, and then each literal initializes an unnamed array with static <a href="/reference/c/language/storage_duration/">storage duration</a> and length just enough to contain the contents of the string literal plus one for the null terminator.</p>

```c
char* p = "\x12" "3"; // creates a static char[3] array holding {'\x12', '3', '\0'}
                      // sets p to point to the first element of the array
```

<p>String literals are <strong>not modifiable</strong> (and in fact may be placed in read-only memory such as <code>.rodata</code>). If a program attempts to modify the static array formed by a string literal, the behavior is undefined.</p>

```c
char* p = "Hello";
p[1] = 'M'; // Undefined behavior
char a[] = "Hello";
a[1] = 'M'; // OK: a is not a string literal
```

<p>It is neither required nor forbidden for identical string literals to refer to the same location in memory. Moreover, overlapping string literals or string literals that are substrings of other string literals may be combined.</p>

```c
"def" == 3+"abcdef"; // may be 1 or 0, implementation-defined
```

<h3 id="Notes">Notes</h3>

<p>A string literal is not necessarily a string; if a string literal has embedded null characters, it represents an array which contains more than one string:</p>

```c
char* p = "abc\0def"; // strlen(p) == 3, but the array has size 8
```

<p>If a valid hex digit follows a hex escape in a string literal, it would fail to compile as an invalid escape sequence, but string concatenation can be used as a workaround:</p>

```c
//char* p = "\xfff"; // error: hex escape sequence out of range
char* p = "\xff""f"; // okay, the literal is char[3] holding {'\xff', 'f', '\0'}
```

<p>String literals can be used to <a href="/reference/c/language/array_initialization/">initialize arrays</a>, and if the size of the array is one less the size of the string literal, the null terminator is ignored:</p>

```c
char a1[] = "abc"; // a1 is char[4] holding {'a', 'b', 'c', '\0'}
char a2[4] = "abc"; // a2 is char[4] holding {'a', 'b', 'c', '\0'}
char a3[3] = "abc"; // a3 is char[3] holding {'a', 'b', 'c'}
```

<p>The encoding of character string literals (1) and wide string literals (5) is implementation-defined. For example, gcc selects them with the <a href="https://gcc.gnu.org/onlinedocs/cpp/Invocation.html" rel="noreferrer" target="_blank">commandline options</a> <code>-fexec-charset</code> and <code>-fwide-exec-charset</code>.</p>

<p>Although mixed wide string literal concatenation is allowed in C11, almost all compilers reject such concatenation (the only known exception is <a href="http://sdcc.sourceforge.net/" rel="noreferrer" target="_blank">SDCC</a>), and its usage experience is unknown. As a result, allowance of mixed wide string literal concatenation is removed in C23.</p>

<h3 id="Example">Example</h3>

```c
#include <inttypes.h>
#include <locale.h>
#include <stddef.h>
#include <stdio.h>
#include <stdlib.h>
#include <uchar.h>
 
int main(void)
{
    char s1[] = "a猫🍌"; // or "a\u732B\U0001F34C"
#if __STDC_VERSION__ >= 202311L
    char8_t
#else
    char
#endif
    s2[] = u8"a猫🍌";
    char16_t s3[] = u"a猫🍌";
    char32_t s4[] = U"a猫🍌";
    wchar_t s5[] = L"a猫🍌";
 
    setlocale(LC_ALL, "en_US.utf8");
    printf("  \"%s\" is a char[%zu] holding     { ", s1, sizeof s1 / sizeof *s1);
    for(size_t n = 0; n < sizeof s1 / sizeof *s1; ++n)
        printf("0x%02X ", +(unsigned char)s1[n]);
    puts("}");
    printf(
#if __STDC_VERSION__ >= 202311L
    "u8\"%s\" is a char8_t[%zu] holding  { "
#else
    "u8\"%s\" is a char[%zu] holding     { "
#endif
, s2, sizeof s2 / sizeof *s2);
    for(size_t n = 0; n < sizeof s2 / sizeof *s2; ++n)
#if __STDC_VERSION__ >= 202311L
       printf("0x%02X ", s2[n]);
#else
       printf("0x%02X ", +(unsigned char)s2[n]);
#endif
    puts("}");
    printf(" u\"a猫🍌\" is a char16_t[%zu] holding { ", sizeof s3 / sizeof *s3);
    for(size_t n = 0; n < sizeof s3 / sizeof *s3; ++n)
       printf("0x%04" PRIXLEAST16" ", s3[n]);
    puts("}");
    printf(" U\"a猫🍌\" is a char32_t[%zu] holding { ", sizeof s4 / sizeof *s4);
    for(size_t n = 0; n < sizeof s4 / sizeof *s4; ++n)
       printf("0x%08" PRIXLEAST32" ", s4[n]);
    puts("}");
    printf(" L\"%ls\" is a wchar_t[%zu] holding  { ", s5, sizeof s5 / sizeof *s5);
    for(size_t n = 0; n < sizeof s5 / sizeof *s5; ++n)
       printf("0x%08X ", (unsigned)s5[n]);
    puts("}");
}
```

<p>Possible output:</p>

```text

  "a猫🍌" is a char[9] holding     { 0x61 0xE7 0x8C 0xAB 0xF0 0x9F 0x8D 0x8C 0x00 }
u8"a猫🍌" is a char[9] holding     { 0x61 0xE7 0x8C 0xAB 0xF0 0x9F 0x8D 0x8C 0x00 }
 u"a猫🍌" is a char16_t[5] holding { 0x0061 0x732B 0xD83C 0xDF4C 0x0000 }
 U"a猫🍌" is a char32_t[4] holding { 0x00000061 0x0000732B 0x0001F34C 0x00000000 }
 L"a猫🍌" is a wchar_t[4] holding  { 0x00000061 0x0000732B 0x0001F34C 0x00000000 }
```
