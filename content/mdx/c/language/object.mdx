<p>C programs create, destroy, access, and manipulate objects.</p>

<p>An object in C is a region of <a href="/reference/c/language/memory_model/">data storage</a> in the execution environment, the contents of which can represent <em>values</em> (a value is the meaning of the contents of an object, when interpreted as having a specific <a href="/reference/c/language/compatible_type/">type</a>).</p>

<p>Every object has</p>

<ul>
<li>
<p>size (can be determined with</p>

<a href="/reference/c/language/sizeof/"><code>sizeof</code></a>

<p>)</p>
</li>
<li>
<p>alignment requirement</p>

(can be determined by <a href="/reference/c/language/alignof/"><code>_Alignof</code></a><span class="std std-until std-c23">(until C23)</span><a href="/reference/c/language/alignof/"><code>alignof</code></a><span class="std std-since std-c23">(since C23)</span>)<span class="std std-since std-c11">(since C11)</span>
</li>
<li>
<a href="/reference/c/language/storage_duration/">storage duration</a>

<p>(automatic, static, allocated, thread-local)</p>
</li>
<li>
<a href="/reference/c/language/lifetime/">lifetime</a>

<p>(equal to storage duration or temporary)</p>
</li>
<li>
<p>effective type (see below)</p>
</li>
<li>
<p>value (which may be indeterminate)</p>
</li>
<li>
<p>optionally, an</p>

<a href="/reference/c/language/identifier/">identifier</a>

<p>that denotes this object.</p>
</li>
</ul>

<p>Objects are created by <a href="/reference/c/language/declarations/">declarations</a>, <a href="/reference/c/memory/">allocation functions</a>, <a href="/reference/c/language/string_literal/">string literals</a>, <a href="/reference/c/language/compound_literal/">compound literals</a>, and by non-lvalue expressions that return <a href="/reference/c/language/lifetime/">structures or unions with array members</a>.</p>

<h3 id="Object_representation">Object representation</h3>

<p>Except for <a href="/reference/c/language/bit_field/">bit-fields</a>, objects are composed of contiguous sequences of one or more bytes, each consisting of <a href="/reference/c/types/limits/">CHAR_BIT</a> bits, and can be copied with <a href="/reference/c/string/byte/memcpy/">memcpy</a> into an object of type <code>unsigned char[n]</code>, where <code>n</code> is the size of the object. The contents of the resulting array are known as <em>object representation</em>.</p>

<p>If two objects have the same object representation, they compare equal (except if they are floating-point NaNs). The reverse is not true: two objects that compare equal may have different object representations because not every bit of the object representation needs to participate in the value. Such bits may be used for padding to satisfy alignment requirement, for parity checks, to indicate trap representations, etc.</p>

<p>If an object representation does not represent any value of the object type, it is known as <em>trap representation</em>. Accessing a trap representation in any way other than reading it through an lvalue expression of character type is undefined behavior. The value of a structure or union is never a trap representation even if any particular member is one.</p>

<p>For the objects of type <code>char</code>, <code>signed char</code>, and <code>unsigned char</code>, every bit of the object representation is required to participate in the value representation and each possible bit pattern represents a distinct value (no padding, trap bits, or multiple representations allowed).</p>

<p>When objects of <a href="/reference/c/language/arithmetic_types/#Integer_types">integer types</a> (<code>short</code>, <code>int</code>, <code>long</code>, <code>long long</code>) occupy multiple bytes, the use of those bytes is implementation-defined, but the two dominant implementations are <em>big-endian</em> (POWER, Sparc, Itanium) and <em>little-endian</em> (x86, x86_64): a big-endian platform stores the most significant byte at the lowest address of the region of storage occupied by the integer, a little-endian platform stores the least significant byte at the lowest address. See <a href="https://en.wikipedia.org/wiki/Endianness" rel="noreferrer" target="_blank">Endianness</a> for detail. See also example below.</p>

<p>Although most implementations do not allow trap representations, padding bits, or multiple representations for integer types, there are exceptions; for example a value of an integer type on Itanium <a href="https://web.archive.org/web/20170830125905/https://blogs.msdn.microsoft.com/oldnewthing/20040119-00/?p=41003" rel="noreferrer" target="_blank">may be a trap representation</a>.</p>

<h3 id="Effective_type">Effective type</h3>

<p>Every object has an <em>effective type</em>, which determines which <a href="/reference/c/language/value_category/">lvalue</a> accesses are valid and which violate the strict aliasing rules.</p>

<p>If the object was created by a <a href="/reference/c/language/declarations/">declaration</a>, the declared type of that object is the object's <em>effective type</em>.</p>

<p>If the object was created by an <a href="/reference/c/memory/">allocation function</a> (including <a href="/reference/c/memory/realloc/">realloc</a>), it has no declared type. Such object acquires an effective type as follows:</p>

<ul>
<li>
<p>The first write to that object through an lvalue that has a type other than character type, at which time the type of that lvalue becomes this object's</p>

<em>effective type</em>

<p>for that write and all subsequent reads.</p>
</li>
<li>
<a href="/reference/c/string/byte/memcpy/">memcpy</a>

<p>or</p>

<a href="/reference/c/string/byte/memmove/">memmove</a>

<p>copy another object into that object, or copy another object into that object as an array of character type, at which time the effective type of the source object (if it had one) becomes the effective type of this object for that write and all subsequent reads.</p>
</li>
<li>
<p>Any other access to the object with no declared type, the effective type is the type of the lvalue used for the access.</p>
</li>
</ul>

<h3 id="Strict_aliasing">Strict aliasing</h3>

<p>Given an object with <em>effective type</em> T1, using an lvalue expression (typically, dereferencing a pointer) of a different type T2 is undefined behavior, unless:</p>

<ul>
<li>
<p>T2 and T1 are</p>

<a href="/reference/c/language/compatible_type/#Compatible_types">compatible types</a>

<p>.</p>
</li>
<li>
<p>T2 is cvr-qualified version of a type that is</p>

<a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a>

<p>with T1.</p>
</li>
<li>
<p>T2 is a signed or unsigned version of a type that is</p>

<a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a>

<p>with T1.</p>
</li>
<li>
<p>T2 is an aggregate type or union type type that includes one of the aforementioned types among its members (including, recursively, a member of a subaggregate or contained union).</p>
</li>
<li>
<p>T2 is a character type (</p>

<code>char</code>

<p>,</p>

<code>signed char</code>

<p>, or</p>

<code>unsigned char</code>

<p>).</p>
</li>
</ul>

```c
int i = 7;
char* pc = (char*)(&i);
 
if (pc[0] == '\x7') // aliasing through char is OK
    puts("This system is little-endian");
else
    puts("This system is big-endian");
 
float* pf = (float*)(&i);
float d = *pf; // UB: float lvalue *p cannot be used to access int
```

<p>These rules control whether when compiling a function that receives two pointers, the compiler must emit code that re-reads one after writing through another:</p>

```c
// int* and double* cannot alias
void f1(int* pi, double* pd, double d)
{
    // the read from *pi can be done only once, before the loop
    for (int i = 0; i < *pi; i++)
        *pd++ = d;
}
```

```c
struct S { int a, b; };
 
// int* and struct S* may alias because S is an aggregate type with a member of type int
void f2(int* pi, struct S* ps, struct S s)
{
    // read from *pi must take place after every write through *ps
    for (int i = 0; i < *pi; i++)
        *ps++ = s;
}
```

<p>Note that <a href="/reference/c/language/restrict/">restrict qualifier</a> can be used to indicate that two pointers do not alias even if the rules above permit them to be.</p>

<p>Note that type-punning may also be performed through the inactive member of a <a href="/reference/c/language/union/">union</a>.</p>

<h3 id="Alignment">Alignment</h3>

<p>Every complete <a href="/reference/c/language/types/#Type_groups">object type</a> has a property called <em>alignment requirement</em>, which is an integer value of type <a href="/reference/c/types/size_t/">size_t</a> representing the number of bytes between successive addresses at which objects of this type can be allocated. The valid alignment values are non-negative integral powers of two.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span></p><p>The alignment requirement of a type can be queried with <a href="/reference/c/language/alignof/"><code>_Alignof</code></a><span class="std std-until std-c23">(until C23)</span><a href="/reference/c/language/alignof/"><code>alignof</code></a><span class="std std-since std-c23">(since C23)</span>.</p></aside>

<p>In order to satisfy alignment requirements of all members of a struct, padding may be inserted after some of its members.</p>

```c
#include <stdalign.h>
#include <stdio.h>
 
// objects of struct S can be allocated at any address
// because both S.a and S.b can be allocated at any address
struct S
{
    char a; // size: 1, alignment: 1
    char b; // size: 1, alignment: 1
}; // size: 2, alignment: 1
 
// objects of struct X must be allocated at 4-byte boundaries
// because X.n must be allocated at 4-byte boundaries
// because int's alignment requirement is (usually) 4
struct X
{
    int n;  // size: 4, alignment: 4
    char c; // size: 1, alignment: 1
    // three bytes padding
}; // size: 8, alignment: 4
 
int main(void)
{
    printf("sizeof(struct S) = %zu\n", sizeof(struct S));
    printf("alignof(struct S) = %zu\n", alignof(struct S));
    printf("sizeof(struct X) = %zu\n", sizeof(struct X));
    printf("alignof(struct X) = %zu\n", alignof(struct X));
}
```

<p>Possible output:</p>

```text
sizeof(struct S) = 2
alignof(struct S) = 1
sizeof(struct X) = 8
alignof(struct X) = 4
```

<p>Each object type imposes its alignment requirement on every object of that type. The weakest (smallest) alignment is the alignment of the types <code>char</code>, <code>signed char</code>, and <code>unsigned char</code>, and equals <code>1</code>. The strictest (largest) <em>fundamental alignment</em> of any type is implementation-definedand equal to the alignment of <a href="/reference/c/types/max_align_t/">max_align_t</a><span class="std std-since std-c11">(since C11)</span>.</p>

<p>Fundamental alignments are supported for objects of all kinds of storage durations.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span></p><p>If an object's alignment is made stricter (larger) than <a href="/reference/c/types/max_align_t/">max_align_t</a> using <a href="/reference/c/language/alignof/"><code>_Alignof</code></a><span class="std std-until std-c23">(until C23)</span><a href="/reference/c/language/alignof/"><code>alignof</code></a><span class="std std-since std-c23">(since C23)</span>, it has <em>extended alignment requirement</em>. A struct or union type whose member has extended alignment is an <em>over-aligned type</em>. It is implementation-defined if over-aligned types are supported, and their support may be different in each kind of <a href="/reference/c/language/storage_duration/">storage duration</a>.</p>

<p>If a struct or union type <code>S</code> does not have any member of an over-aligned type or declared with an alignment specifier that specifies an extended alignment, <code>S</code> has a fundamental alignment.</p>

<p>The <a href="/reference/c/language/atomic/">atomic</a> version of every <a href="/reference/c/language/arithmetic_types/">arithmetic</a> or <a href="/reference/c/language/pointer/">pointer</a> type has a fundamental alignment.</p></aside>
