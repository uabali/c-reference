<p>When an <a href="/reference/c/language/identifier/">identifier</a> is encountered in a C program, a lookup is performed to locate the <a href="/reference/c/language/declarations/">declaration</a> that introduced that identifier and that is currently <a href="/reference/c/language/scope/">in scope</a>. C allows more than one declaration for the same identifier to be in scope simultaneously if these identifiers belong to different categories, called <em>name spaces</em>:</p>

<p class="li-note"><span class="li-num">1)</span>  Label name space: all identifiers declared as <a href="/reference/c/language/statements/#Labels">labels</a>.</p>

<p class="li-note"><span class="li-num">2)</span>  Tag names: all identifiers declared as names of <a href="/reference/c/language/struct/">structs</a>, <a href="/reference/c/language/union/">unions</a> and <a href="/reference/c/language/enum/">enumerated types</a>. Note that all three kinds of tags share one name space.</p>

<p class="li-note"><span class="li-num">3)</span>  Member names: all identifiers declared as members of any one <a href="/reference/c/language/struct/">struct</a> or <a href="/reference/c/language/union/">union</a>. Every struct and union introduces its own name space of this kind.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p class="li-note"><span class="li-num">4)</span>  Global attribute name space: <a href="/reference/c/language/attributes/">attribute tokens</a> defined by the standard or implementation-defined attribute prefixes.</p>

<p class="li-note"><span class="li-num">5)</span>  Non-standard attribute names: attribute names following attribute prefixes. Each attribute prefix has a separate name space for the implementation-defined attributes it introduces.</p></aside>

<p class="li-note"><span class="li-num">6)</span>  All other identifiers, called <em>ordinary identifiers</em> to distinguish from (1-5) (function names, object names, typedef names, enumeration constants).</p>

<p>At the point of lookup, the name space of an identifier is determined by the manner in which it is used:</p>

<p class="li-note"><span class="li-num">1)</span>  identifier appearing as the operand of a <a href="/reference/c/language/goto/">goto statement</a> is looked up in the label name space.</p>

<p class="li-note"><span class="li-num">2)</span>  identifier that follows the keyword <code>struct</code>, <code>union</code>, or <code>enum</code> is looked up in the tag name space.</p>

<p class="li-note"><span class="li-num">3)</span>  identifier that follows the <a href="/reference/c/language/operator_member_access/">member access</a> or member access through pointer operator is looked up in the name space of members of the type determined by the left-hand operand of the member access operator.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p class="li-note"><span class="li-num">4)</span>  identifier that directly appears in an attribute specifier (<code>[[...]]</code>) is looked up in the global attribute name space.</p>

<p class="li-note"><span class="li-num">5)</span>  identifier that follows the <code>::</code> token following an attribute prefix is looked in the name space introduced by the attribute prefix.</p></aside>

<p class="li-note"><span class="li-num">6)</span>  all other identifiers are looked up in the name space of ordinary identifiers.</p>

<h3 id="Notes">Notes</h3>

<p>The names of <a href="/reference/c/preprocessor/replace/">macros</a> are not part of any name space because they are replaced by the preprocessor prior to semantic analysis.</p>

<p>It is common practice to inject struct/union/enum names into the name space of the ordinary identifiers using a <a href="/reference/c/language/typedef/">typedef</a> declaration:</p>

```c
struct A { };       // introduces the name A in tag name space
typedef struct A A; // first, lookup for A after "struct" finds one in tag name space
                    // then introduces the name A in the ordinary name space
struct A* p;        // OK, this A is looked up in the tag name space
A* q;               // OK, this A is looked up in the ordinary name space
```

<p>A well-known example of the same identifier being used across two name spaces is the identifier <code>stat</code> from the POSIX header <code>sys/stat.h</code>. It <a href="http://pubs.opengroup.org/onlinepubs/9699919799/" rel="noreferrer" target="_blank">names a function</a> when used as an ordinary identifier and <a href="http://pubs.opengroup.org/onlinepubs/9699919799/basedefs/sys_stat.h.html" rel="noreferrer" target="_blank">indicates a struct</a> when used as a tag.</p>

<p>Unlike in C++, enumeration constants are not struct members, and their name space is the name space of ordinary identifiers, and since there is no struct scope in C, their scope is the scope in which the struct declaration appears:</p>

```c
struct tagged_union {
   enum {INT, FLOAT, STRING} type;
   union {
      int integer;
      float floating_point;
      char *string;
   };
} tu;
 
tu.type = INT; // OK in C, error in C++
```

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>If a standard attribute, an attribute prefix, or a non-standard attribute name is not supported, the invalid attribute itself is ignored without causing an error.</p></aside>

<h3 id="Example">Example</h3>

```c
void foo (void) { return; } // ordinary name space, file scope
struct foo {      // tag name space, file scope
    int foo;      // member name space for this struct foo, file scope
    enum bar {    // tag name space, file scope
        RED       // ordinary name space, file scope
    } bar;        // member name space for this struct foo, file scope
    struct foo* p; // OK: uses tag/file scope name "foo"
};
enum bar x; // OK: uses tag/file-scope bar
// int foo; // Error: ordinary name space foo already in scope 
//union foo { int a, b; }; // Error: tag name space foo in scope
 
int main(void)
{
    goto foo; // OK uses "foo" from label name space/function scope
 
    struct foo { // tag name space, block scope (hides file scope)
       enum bar x; // OK, uses "bar" from tag name space/file scope
    };
    typedef struct foo foo; // OK: uses foo from tag name space/block scope
                            // defines block-scope ordinary foo (hides file scope)
    (foo){.x=RED}; // uses ordinary/block-scope foo and ordinary/file-scope RED
 
foo:; // label name space, function scope
}
```
