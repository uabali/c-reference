<p>A function declaration introduces an <a href="/reference/c/language/identifier/">identifier</a> that designates a function and, optionally, specifies the types of the function parameters (the <em>prototype</em>). Function declarations (unlike <a href="/reference/c/language/function_definition/">definitions</a>) may appear at block scope as well as file scope.</p>

<h3 id="Syntax">Syntax</h3>

<p>In the <a href="/reference/c/language/declarations/">declaration grammar</a> of a function declaration, the <em>type-specifier</em> sequence, possibly modified by the declarator, designates the <em>return type</em> (which may be any type other than array or function type), and the <em>declarator</em> has one of three forms:</p>

```text
noptr-declarator ( parameter-list ) attr-spec-seq(optional)
noptr-declarator ( identifier-list ) attr-spec-seq(optional)
noptr-declarator ( ) attr-spec-seq(optional)
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>noptr-declarator</em></td><td>-</td><td>any <a href="/reference/c/language/declarations/#Declarators">declarator</a> except unparenthesized pointer declarator. The identifier that is contained in this declarator is the identifier that becomes the function designator.</td></tr>
<tr><td><em>parameter-list</em></td><td>-</td><td>either the single keyword <code>void</code> or a comma-separated list of <em>parameters</em>, which may end with an <a href="/reference/c/language/variadic/">ellipsis parameter</a></td></tr>
<tr><td><em>identifier-list</em></td><td>-</td><td>comma-separated list of identifiers, only possible if this declarator is used as part of old-style <a href="/reference/c/language/function_definition/">function definition</a></td></tr>
<tr><td><em>attr-spec-seq</em></td><td>-</td><td><span class="std std-since std-c23">(C23)</span>an optional list of <a href="/reference/c/language/attributes/">attributes</a>, applied to the function type</td></tr>
</table>

<div class="li-note"><span class="li-num">1)</span>

<p>New-style (C89) function declaration. This declaration both introduces the function designator itself and also serves as a function prototype for any future</p>

<a href="/reference/c/language/operator_other/#Function_call">function call expressions</a>

<p>, forcing conversions from argument expressions to the declared parameter types and compile-time checks for the number of arguments.</p>

```c
int max(int a, int b); // declaration
int n = max(12.01, 3.14); // OK, conversion from double to int
```</div>

<div class="li-note"><span class="li-num">2)</span>

<span class="std std-until std-c23">(until C23)</span>

<p>Old-style (K&amp;R) function definition. This declaration does not introduce a prototype and any future</p>

<a href="/reference/c/language/operator_other/#Function_call">function call expressions</a>

<p>will perform default argument promotions and will invoke undefined behavior if the number of arguments doesn't match the number of parameters.</p>

```c
int max(a, b) 
    int a, b; // definition expects ints; the second call is undefined
{
    return a > b ? a : b;
}
 
int n = max(true, (char)'a'); // calls max with two int args (after promotions)
 
int n = max(12.01f, 3.14); // calls max with two double args (after promotions)
```</div>

<p class="li-note"><span class="li-num">3)</span>  Non-prototype function declaration. This declaration does not introduce a prototype<span class="std std-until std-c23">(until C23)</span>. A new style function declaration equivalent to the <em>parameter-list</em> <code>void</code><span class="std std-since std-c23">(since C23)</span>.</p>

<h3 id="Explanation">Explanation</h3>

<p>The return type of the function, determined by the type specifier in <em>specifiers-and-qualifiers</em> and possibly modified by the <em>declarator</em> as usual in <a href="/reference/c/language/declarations/">declarations</a>, must be a non-array object type or the type <code>void</code>. If the function declaration is not a definition, the return type can be <a href="/reference/c/language/compatible_type/#Incomplete_types">incomplete</a>. The return type cannot be cvr-qualified: any qualified return type is adjusted to its unqualified version for the purpose of constructing the function type.</p>

```c
void f(char *s);                    // return type is void
int sum(int a, int b);              // return type of sum is int.
int (*foo(const void *p))[3];       // return type is pointer to array of 3 int
 
double const bar(void);             // declares function of type double(void)
double (*barp)(void) = bar;         // OK: barp is a pointer to double(void)
double const (*barpc)(void) = barp; // OK: barpc is also a pointer to double(void)
```

<p>Function declarators can be combined with other declarators as long as they can share their type specifiers and qualifiers</p>

```c
int f(void), *fip(), (*pfi)(), *ap[3]; // declares two functions and two objects
inline int g(int), n; // Error: inline qualifier is for functions only
typedef int array_t[3];
array_t a, h(); // Error: array type cannot be a return type for a function
```

<p>If a function declaration appears outside of any function, the identifier it introduces has <a href="/reference/c/language/scope/">file scope</a> and <a href="/reference/c/language/storage_duration/">external linkage</a>, unless <code>static</code> is used or an earlier static declaration is visible. If the declaration occurs inside another function, the identifier has block scope (and also either internal or external linkage).</p>

```c
int main(void)
{
    int f(int); // external linkage, block scope
    f(1); // definition needs to be available somewhere in the program
}
```

<p>The parameters in a declaration that is not part of a <a href="/reference/c/language/function_definition/">function definition</a><span class="std std-until std-c23">(until C23)</span> do not need to be named:</p>

```c
int f(int, int); // declaration
// int f(int, int) { return 7; } // Error: parameters must be named in definitions
// This definition is allowed since C23
```

<p>Each parameter in a <em>parameter-list</em> is a <a href="/reference/c/language/declarations/">declaration</a> that introduced a single variable, with the following additional properties:</p>

<ul>
<li>
<p>the identifier in the declarator is optional</p>

(except if this function declaration is part of a function definition)<span class="std std-until std-c23">(until C23)</span>
</li>
</ul>

```c
int f(int, double); // OK
int g(int a, double b); // also OK
// int f(int, double) { return 1; } // Error: definition must name parameters
// This definition is allowed since C23
```

<ul>
<li>
<p>the only</p>

<a href="/reference/c/language/storage_duration/">storage class specifier</a>

<p>allowed for parameters is</p>

<code>register</code>

<p>, and it is ignored in function declarations that are not definitions</p>
</li>
</ul>

```c
int f(static int x); // Error
int f(int [static 10]); // OK (array index static is not a storage class specifier)
```

<ul>
<li>
<p>any parameter of array type is adjusted to the corresponding pointer type</p>

, which may be qualified if there are qualifiers between the square brackets of the array declarator<span class="std std-since std-c99">(since C99)</span>
</li>
</ul>

```c
int f(int[]); // declares int f(int*)
int g(const int[10]); // declares int g(const int*)
int h(int[const volatile]); // declares int h(int * const volatile)
int x(int[*]); // declares int x(int*)
```

<ul>
<li>
<p>any parameter of function type is adjusted to the corresponding pointer type</p>
</li>
</ul>

```c
int f(char g(double)); // declares int f(char (*g)(double))
int h(int(void)); // declares int h(int (*)(void))
```

<ul>
<li>
<p>the parameter list may terminate with</p>

<code>, ...</code>

or be <code>...</code><span class="std std-since std-c23">(since C23)</span>

<p>, see</p>

<a href="/reference/c/language/variadic/">variadic functions</a>

<p>for details.</p>
</li>
</ul>

```c
int f(int, ...);
```

<ul>
<li>
<p>parameters cannot have type</p>

<code>void</code>

<p>(but can have type pointer to void). The special parameter list that consists entirely of the keyword</p>

<code>void</code>

<p>is used to declare functions that take no parameters.</p>
</li>
</ul>

```c
int f(void); // OK
int g(void x); // Error
```

<ul>
<li>
<p>any identifier that appears in a parameter list that could be treated as a typedef name or as a parameter name is treated as a typedef name:</p>

<code>int f(size_t, uintptr_t)</code>

<p>is parsed as a new-style declarator for a function taking two unnamed parameters of type size_t and uintptr_t, not an old-style declarator that begins the definition of a function taking two parameters named "size_t" and "uintptr_t"</p>
</li>
<li>
<p>parameters may have incomplete type</p>

and may use the VLA notation [*]<span class="std std-since std-c99">(since C99)</span>

<p>(except that in a</p>

<a href="/reference/c/language/function_definition/">function definition</a>

<p>, the parameter types after array-to-pointer and function-to-pointer adjustment must be complete)</p>
</li>
</ul>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p><a href="/reference/c/language/attributes/">Attribute specifier sequences</a> can also applied to function parameters.</p></aside>

<p>See <a href="/reference/c/language/operator_other/#Function_call">function call operator</a> for other details on the mechanics of a function call and <a href="/reference/c/language/return/">return</a> for returning from functions.</p>

<h3 id="Notes">Notes</h3>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p>Unlike in C++, the declarators <code>f()</code> and <code>f(void)</code> have different meaning: the declarator <code>f(void)</code> is a new-style (prototype) declarator that declares a function that takes no parameters. The declarator <code>f()</code> is a declarator that declares a function that takes <em>unspecified</em> number of parameters (unless used in a function definition)</p>

```c
int f(void); // declaration: takes no parameters
int g(); // declaration: takes unknown parameters
 
int main(void) {
    f(1); // compile-time error
    g(2); // undefined behavior
}
 
int f(void) { return 1; } // actual definition
int g(a,b,c,d) int a,b,c,d; { return 2; } // actual definition
```</aside>

<p>Unlike in a <a href="/reference/c/language/function_definition/">function definition</a>, the parameter list may be inherited from a typedef</p>

```c
typedef int p(int q, int r); // p is a function type int(int, int)
p f; // declares int f(int, int)
```

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c99">(until C99)</span></p><p>In C89, <em>specifiers-and-qualifiers</em> was optional, and if omitted, the return type of the function defaulted to <code>int</code> (possibly amended by the <em>declarator</em>).</p>

```c
*f() { // function returning int*
   return NULL;
}
```</aside>
