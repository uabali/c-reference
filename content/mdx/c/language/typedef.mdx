<p>The <em>typedef declaration</em> provides a way to declare an identifier as a type alias, to be used to replace a possibly complex <a href="/reference/c/language/compatible_type/#Type_names">type name</a></p>

<p>The keyword <code>typedef</code> is used in a <a href="/reference/c/language/declarations/">declaration</a>, in the grammatical position of a <a href="/reference/c/language/storage_duration/">storage-class specifier</a>, except that it does not affect storage or linkage:</p>

```c
typedef int int_t; // declares int_t to be an alias for the type int
typedef char char_t, *char_p, (*fp)(void); // declares char_t to be an alias for char
                                           // char_p to be an alias for char*
                                           // fp to be an alias for char(*)(void)
```

<h3 id="Explanation">Explanation</h3>

<p>If a <a href="/reference/c/language/declarations/">declaration</a> uses <code>typedef</code> as storage-class specifier, every declarator in it defines an identifier as an alias to the type specified. Since only one storage-class specifier is permitted in a declaration, typedef declaration cannot be <a href="/reference/c/language/storage_duration/">static or extern</a>.</p>

<p>typedef declaration does not introduce a distinct type, it only establishes a synonym for an existing type, thus typedef names are <a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a> with the types they alias. Typedef names share the <a href="/reference/c/language/name_space/">name space</a> with ordinary identifiers such as enumerators, variables and function.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>A typedef for a VLA can only appear at block scope. The length of the array is evaluated each time the flow of control passes over the typedef declaration, as opposed to the declaration of the array itself:</p>

```c
void copyt(int n)
{
    typedef int B[n]; // B is a VLA, its size is n, evaluated now
    n += 1;
    B a; // size of a is n from before +=1
    int b[n]; // a and b are different sizes
    for (int i = 1; i < n; i++)
        a[i-1] = b[i];
}
```</aside>

<h3 id="Notes">Notes</h3>

<p>typedef name may be an <a href="/reference/c/language/compatible_type/#Incomplete_types">incomplete type</a>, which may be completed as usual:</p>

```c
typedef int A[]; // A is int[]
A a = {1, 2}, b = {3,4,5}; // type of a is int[2], type of b is int[3]
```

<p>typedef declarations are often used to inject names from the tag <a href="/reference/c/language/name_space/">name space</a> into the ordinary name space:</p>

```c
typedef struct tnode tnode; // tnode in ordinary name space
                            // is an alias to tnode in tag name space
struct tnode {
    int count;
    tnode *left, *right; // same as struct tnode *left, *right;
}; // now tnode is also a complete type
tnode s, *sp; // same as struct tnode s, *sp;
```

<p>They can even avoid using the tag name space at all:</p>

```c
typedef struct { double hi, lo; } range;
range z, *zp;
```

<p>Typedef names are also commonly used to simplify the syntax of complex declarations:</p>

```c
// array of 5 pointers to functions returning pointers to arrays of 3 ints
int (*(*callbacks[5])(void))[3];
 
// same with typedefs
typedef int arr_t[3]; // arr_t is array of 3 int
typedef arr_t* (*fp)(void); // pointer to function returning arr_t*
fp callbacks[5];
```

<p>Libraries often expose system-dependent or configuration-dependent types as typedef names, to present a consistent interface to the users or to other library components:</p>

```c
#if defined(_LP64)
typedef int     wchar_t;
#else
typedef long    wchar_t;
#endif
```
