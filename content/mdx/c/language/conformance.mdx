<p><em>Conformance</em> has a three-fold definition:</p>

<ul>
<li>
<em>strictly conforming program</em>

<p>- uses only well-defined language constructs, that is constructs with a single behavior. It excludes unspecified, undefined, or implementation-defined behavior, and does not exceed any minimum implementation limit.</p>
</li>
<li>
<em>conforming program</em>

<p>- acceptable to a conforming implementation.</p>
</li>
<li>
<em>conforming implementation</em>

<p>-</p>

<ul>
<li>
<p>A conforming hosted implementation shall accept any strictly conforming program.</p>
</li>
<li>
<p>A conforming freestanding implementation shall accept any strictly conforming program in which the use of the features specified in the library clause (clause 7) is confined to the contents of the freestanding standard library headers (see below).</p>
</li>
<li>
<p>A conforming implementation may have extensions (including additional library functions), provided they do not alter the behavior of any strictly conforming program.</p>
</li>
</ul>
</li>
</ul>

<h3 id="Explanation">Explanation</h3>

<p>The standard does not define any minimum implementation limit on translation units. A hosted environment has an operating system; a freestanding environment does not. A program running in a hosted environment may use all features described in the library clause (clause 7); a program running in a freestanding environment may use a subset of library features required by clause 4.</p>

<h4 id="Freestanding_standard_library_headers">Freestanding standard library headers</h4>

<p>All standard library features in every fully freestanding header are required to be provided by a freestanding implementation.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Some standard library headers are conditionally freestanding.</p>

<ul>
<li>
<p>If the implementation predefines the macro</p>

<code>__STDC_IEC_60559_BFP__</code>

<p>or</p>

<code>__STDC_IEC_60559_DFP__</code>

<p>, then</p>

<a href="/reference/c/numeric/math/"><code>&lt;math.h&gt;</code></a>

<p>and</p>

<a href="/reference/c/numeric/fenv/"><code>&lt;fenv.h&gt;</code></a>

<p>are fully freestanding headers. However, the behavior of functions in these headers is required to be well-defined in a freestanding environment only if a program does not set the state of the</p>

<a href="/reference/c/preprocessor/impl/#Standard_pragmas"><code>FENV_ACCESS</code></a>

<p>pragma to</p>

<code>ON</code>

<p>.</p>
</li>
</ul>

<p>Some standard library headers are partially freestanding.</p>

<ul>
<li>
<p>In</p>

<a href="/reference/c/program/"><code>&lt;stdlib.h&gt;</code></a>

<p>,</p>

<a href="/reference/c/program/memalignment/"><code>memalignment</code></a>

<p>is freestanding. Additionally, when</p>

<code>__STDC_IEC_60559_BFP__</code>

<p>or</p>

<code>__STDC_IEC_60559_DFP__</code>

<p>are predefined, numeric conversion functions (</p>

<code>atoX</code>

<p>,</p>

<code>strtoX</code>

<p>, and</p>

<code>strfromX</code>

<p>) are also freestanding, while their behavior is required to be well-defined in a freestanding environment only if a program does not set the state of the</p>

<a href="/reference/c/preprocessor/impl/#Standard_pragmas"><code>FENV_ACCESS</code></a>

<p>pragma to</p>

<code>ON</code>

<p>. No other component in</p>

<a href="/reference/c/program/"><code>&lt;stdlib.h&gt;</code></a>

<p>is required to be to be provided by a freestanding implementation.</p>
</li>
<li>
<p>In</p>

<a href="/reference/c/string/byte/"><code>&lt;string.h&gt;</code></a>

<p>,</p>

<a href="/reference/c/string/byte/strdup/"><code>strdup</code></a>

<p>,</p>

<a href="/reference/c/string/byte/strndup/"><code>strndup</code></a>

<p>,</p>

<a href="/reference/c/string/byte/strcoll/">strcoll</a>

<p>,</p>

<a href="/reference/c/string/byte/strxfrm/">strxfrm</a>

<p>,</p>

<a href="/reference/c/string/byte/strtok/">strtok</a>

<p>, and</p>

<a href="/reference/c/string/byte/strerror/">strerror</a>

<p>are not required to be provided by a freestanding implementation.</p>
</li>
</ul></aside>
