<p>Performs explicit type conversion</p>

<h3 id="Syntax">Syntax</h3>

```text
( type-name ) expression
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>type-name</em></td><td>-</td><td>either the type <code>void</code> or any <a href="/reference/c/language/compatible_type/#Type_groups">scalar type</a></td></tr>
<tr><td><em>expression</em></td><td>-</td><td>any <a href="/reference/c/language/expressions/">expression</a> of <a href="/reference/c/language/compatible_type/#Type_groups">scalar type</a> (unless <em>type-name</em> is void, in which case it can be anything)</td></tr>
</table>

<h3 id="Explanation">Explanation</h3>

<p>If <em>type-name</em> is <code>void</code>, then <em>expression</em> is evaluated for its side-effects and its returned value is discarded, same as when <em>expression</em> is used on its own, as an <a href="/reference/c/language/statements/#Expression_statements">expression statement</a>.</p>

<p>Otherwise, if <em>type-name</em> is exactly the type of <em>expression</em>, nothing is done (except that if <em>expression</em> has floating type and is represented with greater range and precision than its type indicates -- see below)</p>

<p>Otherwise, the value of <em>expression</em> is converted to the type named by <em>type-name</em>, as follows:</p>

<p>Every <a href="/reference/c/language/conversion/">implicit conversion as if by assignment</a> is allowed.</p>

<p>In addition to the implicit conversions, the following conversions are allowed:</p>

<ul>
<li>
<p>Any integer can be cast to any pointer type. Except for the null pointer constants such as</p>

<a href="/reference/c/types/NULL/">NULL</a>

<p>(which</p>

<a href="/reference/c/language/conversion/">doesn't need a cast</a>

<p>), the result is implementation-defined, may not be correctly aligned, may not point to an object of the referenced type, and may be a</p>

<a href="/reference/c/language/object/">trap representation</a>

<p>.</p>
</li>
<li>
<p>Any pointer type can be cast to any integer type. The result is implementation-defined, even for null pointer values (they do not necessarily result in the value zero). If the result cannot be represented in the target type, the behavior is undefined (unsigned integers do not implement modulo arithmetic on a cast from pointer)</p>
</li>
<li>
<p>Any pointer to object can be cast to any other pointer to object. If the value is not correctly aligned for the target type, the behavior is undefined. Otherwise, if the value is converted back to the original type, it compares equal to the original value. If a pointer to object is cast to pointer to any character type, the result points at the lowest byte of the object and may be incremented up to sizeof the target type (in other words, can be used to examine</p>

<a href="/reference/c/language/object/">object representation</a>

<p>or to make a copy via</p>

<a href="/reference/c/string/byte/memcpy/">memcpy</a>

<p>or</p>

<a href="/reference/c/string/byte/memmove/">memmove</a>

<p>).</p>
</li>
<li>
<p>Any pointer to function can be cast to a pointer to any other function type. If the resulting pointer is converted back to the original type, it compares equal to the original value. If the converted pointer is used to make a function call, the behavior is undefined (unless the function types are</p>

<a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a>

<p>)</p>
</li>
<li>
<p>When casting between pointers (either object or function), if the original value is a null pointer value of its type, the result is the correct null pointer value for the target type.</p>
</li>
</ul>

<p>In any case (both when executing an implicit conversion and in the same-type cast), if <em>expression</em> and <em>type-name</em> are floating types and <em>expression</em> is represented with greater range and precision than its type indicates (see <a href="/reference/c/types/limits/FLT_EVAL_METHOD/">FLT_EVAL_METHOD</a>), the range and precision are stripped off to match the target type.</p>

<p>The <a href="/reference/c/language/value_category/">value category</a> of the cast expression is always non-lvalue.</p>

<h3 id="Notes">Notes</h3>

<p>Because <a href="/reference/c/language/const/"><code>const</code></a>, <a href="/reference/c/language/volatile/"><code>volatile</code></a>, <a href="/reference/c/language/restrict/"><code>restrict</code></a>, and <a href="/reference/c/language/atomic/"><code>_Atomic</code></a> qualifiers have effect on <a href="/reference/c/language/value_category/">lvalues</a> only, a cast to a cvr-qualified or atomic type is exactly equivalent to the cast to the corresponding unqualified type.</p>

<p>The cast to <code>void</code> is sometimes useful to silence compiler warnings about unused results.</p>

<p>The conversions not listed here are not allowed. In particular,</p>

<ul>
<li>
<p>there are no conversions between pointers and floating types</p>
</li>
<li>
<p>there are no conversions between pointers to functions and pointers to objects (including</p>

<code>void*</code>

<p>)</p>
</li>
</ul>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>If the implementation provides <a href="/reference/c/types/integer/">intptr_t</a> and/or <a href="/reference/c/types/integer/">uintptr_t</a>, then a cast from a pointer to an object type (including <em>cv</em> <code>void</code>) to these types is always well-defined. However, this is not guaranteed for a function pointer.</p></aside>

<p>Note that conversions between function pointers and object pointers are accepted as extensions by many compilers, and expected by some usages of <a href="https://pubs.opengroup.org/onlinepubs/9699919799/functions/dlsym.html" rel="noreferrer" target="_blank">POSIX <code>dlsym()</code> function</a>.</p>

<h3 id="Example">Example</h3>

```c
#include <stdio.h>
 
int main(void)
{
    // examining object representation is a legitimate use of cast
    double d = 3.14;
    printf("The double %.2f (%a) is: ", d, d);
    for (size_t n = 0; n < sizeof d; ++n)
        printf("0x%02x ", ((unsigned char*)&d)[n]);
 
    // edge cases
    struct S { int x; } s;
//    (struct S)s; // error; not a scalar type
                   // even though casting to the same type does nothing
    (void)s; // okay to cast any type to void
}
```

<p>Possible output:</p>

```text
The double 3.14 (0x1.91eb851eb851fp+1) is: 0x1f 0x85 0xeb 0x51 0xb8 0x1e 0x09 0x40
```
