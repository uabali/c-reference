<p>Assignment and compound assignment operators are binary operators that modify the variable to their left using the value to their right.</p>

<table class="ref-table">
<tr><th>Operator</th><th>Operator name</th><th>Example</th><th>Description</th><th>Equivalent of</th></tr>
<tr><td><code>=</code></td><td>basic assignment</td><td><code>a = b</code></td><td><strong>a</strong> becomes equal to <strong>b</strong></td><td>N/A</td></tr>
<tr><td><code>+=</code></td><td>addition assignment</td><td><code>a += b</code></td><td><strong>a</strong> becomes equal to the addition of <strong>a</strong> and <strong>b</strong></td><td><code>a = a + b</code></td></tr>
<tr><td><code>-=</code></td><td>subtraction assignment</td><td><code>a -= b</code></td><td><strong>a</strong> becomes equal to the subtraction of <strong>b</strong> from <strong>a</strong></td><td><code>a = a - b</code></td></tr>
<tr><td><code>*=</code></td><td>multiplication assignment</td><td><code>a *= b</code></td><td><strong>a</strong> becomes equal to the product of <strong>a</strong> and <strong>b</strong></td><td><code>a = a * b</code></td></tr>
<tr><td><code>/=</code></td><td>division assignment</td><td><code>a /= b</code></td><td><strong>a</strong> becomes equal to the division of <strong>a</strong> by <strong>b</strong></td><td><code>a = a / b</code></td></tr>

<h3 id="Simple_assignment">Simple assignment</h3>

<p>The simple assignment operator expressions have the form</p>

```text
lhs = rhs
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>lhs</em></td><td>-</td><td><a href="/reference/c/language/value_category/">modifiable lvalue</a> expression of any complete object type</td></tr>
<tr><td><em>rhs</em></td><td>-</td><td>expression of any type <a href="/reference/c/language/conversion/">implicitly convertible</a> to <em>lhs</em> or <a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a> with <em>lhs</em></td></tr>
</table>

<p>Assignment performs <a href="/reference/c/language/conversion/">implicit conversion</a> from the value of <em>rhs</em> to the type of <em>lhs</em> and then replaces the value in the object designated by <em>lhs</em> with the converted value of <em>rhs</em>.</p>

<p>Assignment also returns the same value as what was stored in <code>lhs</code> (so that expressions such as <code>a = b = c</code> are possible). The <a href="/reference/c/language/value_category/">value category</a> of the assignment operator is non-lvalue (so that expressions such as <code>(a=b)=c</code> are invalid).</p>

<p><em>rhs</em> and <em>lhs</em> must satisfy one of the following:</p>

<em>lhs</em>

<p>and</p>

<p>or</p>

<a href="/reference/c/language/union/">union</a>

<p>type, or..</p>
</li>

<p>must be</p>

<a href="/reference/c/language/conversion/">implicitly convertible</a>

<p>to</p>

<em>lhs</em>

<p>, which implies</p>
</li>
</ul>

<h4 id="Notes">Notes</h4>

<p>If <em>rhs</em> and <em>lhs</em> overlap in memory (e.g. they are members of the same union), the behavior is undefined unless the overlap is exact and the types are <a href="/reference/c/language/compatible_type/#Compatible_types">compatible</a>.</p>

<p>Although arrays are not assignable, an array wrapped in a struct is assignable to another object of the same (or compatible) struct type.</p>

<p>The side effect of updating <em>lhs</em> is <a href="/reference/c/language/eval_order/">sequenced after</a> the value computations, but not the side effects of <em>lhs</em> and <em>rhs</em> themselves and the evaluations of the operands are, as usual, unsequenced relative to each other (so the expressions such as <code>i=++i</code>; are undefined)</p>

<p>Assignment strips extra range and precision from floating-point expressions (see <a href="/reference/c/types/limits/FLT_EVAL_METHOD/">FLT_EVAL_METHOD</a>).</p>

<p>In C++, assignment operators are lvalue expressions, not so in C.</p>

```c
#include <stdio.h>
 
int main(void)
{
    // integers
    int i = 1, j = 2, k = 3; // initialization, not assignment
 
    i = j = k;   // values of i and j are now 3
//  (i = j) = k; // Error: lvalue required
    printf("%d %d %d\n", i, j, k);
 
    // pointers
    const char c = 'A'; // initialization; not assignment
    const char *p = &c;  // initialization; not assignment
    const char **cpp = &p; // initialization; not assignment
 
//  cpp = &p;   // Error: char** is not convertible to const char**
    *cpp = &c;  // OK, char* is convertible to const char*
    printf("%c \n", **cpp);
    cpp = 0;    // OK, null pointer constant is convertible to any pointer
 
    // arrays
    int arr1[2] = {1,2}, arr2[2] = {3, 4};
//  arr1 = arr2; // Error: cannot assign to an array
    printf("arr1[0]=%d arr1[1]=%d arr2[0]=%d arr2[1]=%d\n",
            arr1[0],   arr1[1],   arr2[0],   arr2[1]);
 
    struct { int arr[2]; } sam1 = { {5, 6} }, sam2 = { {7, 8} };
    sam1 = sam2; // OK: can assign arrays wrapped in structs
 
    printf("%d %d \n", sam1.arr[0], sam1.arr[1]);
}
```

<p>Output:</p>

```text
3 3 3
A
arr1[0]=1 arr1[1]=2 arr2[0]=3 arr2[1]=4
7 8
```

<h3 id="Compound_assignment">Compound assignment</h3>

<p>The compound assignment operator expressions have the form</p>

```text
lhs op rhs
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>op</em></td><td>-</td><td>one of <code>*=</code>, <code>/=</code> <code>%=</code>, <code>+=</code> <code>-=</code>, <code>&lt;&lt;=</code>, <code>&gt;&gt;=</code>, <code>&amp;=</code>, <code>^=</code>, <code>|=</code></td></tr>
<tr><td><em>lhs</em>, <em>rhs</em></td><td>-</td><td>expressions with <a href="/reference/c/language/arithmetic_types/">arithmetic types</a> (where <em>lhs</em> may be qualified or atomic), except when <em>op</em> is <code>+=</code> or <code>-=</code>, which also accept pointer types with the same restrictions as + and -</td></tr>
</table>

<p>The expression <em>lhs</em> <em>@=</em> <em>rhs</em> is exactly the same as <em>lhs</em> <code>=</code> <em>lhs</em> <em>@</em> <code>(</code> <em>rhs</em> <code>)</code>, except that <em>lhs</em> is evaluated only once.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span></p><p>If <em>lhs</em> has <a href="/reference/c/language/atomic/">atomic</a> type, the operation behaves as a single atomic read-modify-write operation with memory order <a href="/reference/c/atomic/memory_order/">memory_order_seq_cst</a>.</p>

<p>For integer atomic types, the compound assignment <code>@=</code> is equivalent to:</p>

```c
T1* addr = &lhs;
T2 val = rhs;
T1 old = *addr;
T1 new;
do { new = old @ val } while (!atomic_compare_exchange_strong(addr, &old, new);
```</aside>

```c
#include <stdio.h>
 
int main(void)
{
    int x = 10; 
    int hundred = 100; 
    int ten = 10; 
    int fifty = 50; 
 
    printf("%d %d %d %d\n", x, hundred, ten, fifty);
 
    hundred *= x; 
    ten     /= x; 
    fifty   %= x; 
 
    printf("%d %d %d %d\n", x, hundred, ten, fifty);
 
    return 0;
}
```

<p>Output:</p>

```text
10 100 10 50
10 1000 1 0
```
