<p>A function definition associates the function body (a sequence of declarations and statements) with the function name and parameter list. Unlike <a href="/reference/c/language/function_declaration/">function declaration</a>, function definitions are allowed at file scope only (there are no nested functions).</p>

<p>C supports two different forms of function definitions:</p>

```text
attr-spec-seq(optional) specifiers-and-qualifiers parameter-list-declarator function-body
specifiers-and-qualifiers identifier-list-declarator declaration-list function-body
```

<p>where</p>

<table class="ref-table ref-params">
<tr><td><em>attr-spec-seq</em></td><td>-</td><td><span class="std std-since std-c23">(C23)</span>an optional list of <a href="/reference/c/language/attributes/">attributes</a>, applied to the function</td></tr>
<tr><td><em>specifiers-and-qualifiers</em></td><td>-</td><td><p>a combination of</p>

<ul>
<li>
<a href="/reference/c/language/declarations/">type specifiers</a>

<p>that, possibly modified by the declarator, form the</p>

<em>return type</em>
</li>
<li>
<a href="/reference/c/language/storage_duration/">storage class specifiers</a>

<p>, which determine the linkage of the identifier (</p>

<code>static</code>

<p>,</p>

<code>extern</code>

<p>, or none)</p>
</li>
<li>
<p>function specifiers</p>

<a href="/reference/c/language/inline/"><code>inline</code></a>

<p>,</p>

<a href="/reference/c/language/_Noreturn/"><code>_Noreturn</code></a>

<p>, or none</p>
</li>
</ul></td></tr>
<tr><td><em>parameter-list-declarator</em></td><td>-</td><td>a declarator for a function type which uses a <a href="/reference/c/language/function_declaration/">parameter list</a> to designate function parameters</td></tr>
<tr><td><em>identifier-list-declarator</em></td><td>-</td><td>a declarator for a function type which uses a <a href="/reference/c/language/function_declaration/">identifier list</a> to designate function parameters</td></tr>
<tr><td><em>declaration-list</em></td><td>-</td><td>sequence of declarations that declare every identifier in <em>identifier-list-declarator</em>. These declarations cannot use initializers and the only <a href="/reference/c/language/storage_duration/">storage-class specifier</a> allowed is <code>register</code>.</td></tr>
<tr><td><em>function-body</em></td><td>-</td><td>a <a href="/reference/c/language/statements/#Compound_statements">compound statement</a>, that is a brace-enclosed sequence of declarations and statements, that is executed whenever this function is called</td></tr>
</table>

<div class="li-note"><span class="li-num">1)</span>

<p>New-style (C89) function definition. This definition both introduces the function itself and serves as a function prototype for any future</p>

<a href="/reference/c/language/operator_other/#Function_call">function call expressions</a>

<p>, forcing conversions from argument expressions to the declared parameter types.</p>

```c
int max(int a, int b)
{
    return a>b?a:b;
}
 
double g(void)
{
    return 0.1;
}
```</div>

<div class="li-note"><span class="li-num">2)</span>

<span class="std std-until std-c23">(until C23)</span>

<p>Old-style (K&amp;R) function definition. This definition does not behave as a prototype and any future</p>

<a href="/reference/c/language/operator_other/#Function_call">function call expressions</a>

<p>will perform default argument promotions.</p>

```c
int max(a, b)
int a, b;
{
    return a>b?a:b;
}
double g()
{
    return 0.1;
}
```</div>

<h3 id="Explanation">Explanation</h3>

<p>As with <a href="/reference/c/language/function_declaration/">function declarations</a>, the return type of the function, determined by the type specifier in <em>specifiers-and-qualifiers</em> and possibly modified by the <em>declarator</em> as usual in <a href="/reference/c/language/declarations/">declarations</a>, must be a complete non-array object type or the type <code>void</code>. If the return type would be cvr-qualified, it is adjusted to its unqualified version for the purpose of constructing the function type.</p>

```c
void f(char *s) { puts(s); } // return type is void
int sum(int a, int b) { return a+b; } // return type is int
int (*foo(const void *p))[3] { // return type is pointer to array of 3 int
    return malloc(sizeof(int[3]));
}
```

<p>As with <a href="/reference/c/language/function_declaration/">function declarations</a>, the types of the parameters are adjusted from functions to pointers and from arrays to pointers for the purpose of constructing the function type and the top-level cvr-qualifiers of all parameter types are ignored for the purpose of determining <a href="/reference/c/language/compatible_type/#Compatible_types">compatible function type</a>.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p>Unlike <a href="/reference/c/language/function_declaration/">function declarations</a>, unnamed formal parameters are not allowed (otherwise, there would be conflicts in old-style (K&amp;R) function definitions), they must be named even if they are not used within the function. The only exception is the special parameter list <code>(void)</code>.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>Formal parameters may be unnamed in function definitions, because old-style (K&amp;R) function definitions has been removed. Unnamed parameters are inaccessible by name within the function body.</p></aside>

```c
int f(int, int); // declaration
// int f(int, int) { return 7; } // Error until C23, OK since C23
int f(int a, int b) { return 7; } // definition
int g(void) { return 8; } // OK: void doesn't declare a parameter
```

<p>Within the function body, every named parameter is an <a href="/reference/c/language/value_category/">lvalue</a> expression, they have automatic <a href="/reference/c/language/storage_duration/">storage duration</a> and <a href="/reference/c/language/scope/">block scope</a>. The layout of the parameters in memory (or if they are stored in memory at all) is unspecified: it is a part of the <a href="https://en.wikipedia.org/wiki/Calling_convention" rel="noreferrer" target="_blank">calling convention</a>.</p>

```c
int main(int ac, char **av)
{
    ac = 2; // parameters are lvalues
    av = (char *[]){"abc", "def", NULL};
    f(ac, av);
}
```

<p>See <a href="/reference/c/language/operator_other/#Function_call">function call operator</a> for other details on the mechanics of a function call and <a href="/reference/c/language/return/">return</a> for returning from functions.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><h3 id="func">__func__</h3>

<p>Within every <em>function-body</em>, the special predefined variable <code>__func__</code> with block scope and static storage duration is available, as if defined immediately after the opening brace by</p>

```c
static const char __func__[] = "function name";
```

<p>This special identifier is sometimes used in combination with the <a href="/reference/c/preprocessor/replace/">predefined macro constants</a> <code>__FILE__</code> and <code>__LINE__</code>, for example, by <a href="/reference/c/error/assert/">assert</a>.</p></aside>

<h3 id="Notes">Notes</h3>

<p>The argument list must be explicitly present in the declarator, it cannot be inherited from a typedef</p>

```c
typedef int p(int q, int r); // p is a function type int(int, int)
p f { return q + r; } // Error
```

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c99">(until C99)</span></p><p>In C89, <em>specifiers-and-qualifiers</em> was optional, and if omitted, the return type of the function defaulted to <code>int</code> (possibly amended by the <em>declarator</em>).</p>

<p>In addition, old-style definition didn't require a declaration for every parameter in <em>declaration-list</em>. Any parameter whose declaration was missing had type <code>int</code></p>

```c
max(a, b) // a and b have type int, return type is int
{
    return a>b?a:b;
}
```</aside>
