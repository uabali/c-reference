<p>Allows values of integer type to be used in expressions directly.</p>

<h3 id="Syntax">Syntax</h3>

<p>An integer constant is a <a href="/reference/c/language/value_category/">non-lvalue</a> expression of the form</p>

```text
decimal-constant integer-suffix (optional)
octal-constant integer-suffix (optional)
hex-constant integer-suffix (optional)
binary-constant integer-suffix (optional)
```

<p>where</p>

<ul>
<li>
<em>decimal-constant</em>

<p>is a non-zero decimal digit (</p>

<code>1</code>

<p>,</p>

<code>2</code>

<p>,</p>

<code>3</code>

<p>,</p>

<code>4</code>

<p>,</p>

<code>5</code>

<p>,</p>

<code>6</code>

<p>,</p>

<code>7</code>

<p>,</p>

<code>8</code>

<p>,</p>

<code>9</code>

<p>), followed by zero or more decimal digits (</p>

<code>0</code>

<p>,</p>

<code>1</code>

<p>,</p>

<code>2</code>

<p>,</p>

<code>3</code>

<code>4</code>

<p>,</p>

<code>5</code>

<p>,</p>

<p>,</p>

<p>,</p>

<code>8</code>

<p>,</p>

<code>9</code>

</li>

<h3 id="Explanation">Explanation</h3>

<p class="li-note"><span class="li-num">1)</span>  Decimal integer constant (base 10, the first digit is the most significant).</p>

<p class="li-note"><span class="li-num">2)</span>  Octal integer constant (base 8, the first digit is the most significant).</p>

<p class="li-note"><span class="li-num">3)</span>  Hexadecimal integer constant (base 16, the first digit is the most significant, the letters <code>a</code> through <code>f</code> represent the decimal values 10 through 15).</p>

<p class="li-note"><span class="li-num">4)</span>  Binary integer constant (base 2, the first digit is the most significant).</p>

<p>The following variables are initialized to the same value:</p>

```c
int d = 42;
int o = 052;
int x = 0x2a;
int X = 0X2A;
int b = 0b101010; // C23
```

<p>The following variables are also initialized to the same value:</p>

```c
unsigned long long l1 = 18446744073709550592ull; // C99
unsigned long long l2 = 18'446'744'073'709'550'592llu; // C23
unsigned long long l3 = 1844'6744'0737'0955'0592uLL; // C23
unsigned long long l4 = 184467'440737'0'95505'92LLU; // C23
```

<p>If the value of the integer constant is too big to fit in any of the types allowed by suffix/base combination, it does not have suffixes <code>wb</code>, <code>WB</code>, <code>uwb</code>, or <code>UWB</code><span class="std std-since std-c23">(since C23)</span> and the compiler supports extended integer types (such as <code>__int128</code>), the constant may be given the extended integer type; otherwise, the program is ill-formed.</p>

<h3 id="Notes">Notes</h3>

<p>Letters in the integer constants are case-insensitive: <code>0xDeAdBaBeU</code> and <code>0XdeadBABEu</code> represent the same number (one exception is the <em>long-long-suffix</em>, which is either <code>ll</code> or <code>LL</code>, never <code>lL</code> or <code>Ll</code>)<span class="std std-since std-c99">(since C99)</span>.</p>

<p>There are no negative integer constants. Expressions such as <code>-1</code> apply the <a href="/reference/c/language/operator_arithmetic/">unary minus operator</a> to the value represented by the constant.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>When used in a controlling expression of <a href="/reference/c/preprocessor/conditional/"><code>#if</code></a> or <a href="/reference/c/preprocessor/conditional/"><code>#elif</code></a>, all signed integer constants act as if they have type <a href="/reference/c/types/integer/">intmax_t</a> and all unsigned integer constants act as if they have type <a href="/reference/c/types/integer/">uintmax_t</a>.</p></aside>

<p>Integer constants may be used in <a href="/reference/c/language/constant_expression/">integer constant expressions</a>.</p>

<p>Due to <a href="/reference/c/language/translation_phases/#maximal_munch">maximal munch</a>, hexadecimal integer constants ending in <code>e</code> and <code>E</code>, when followed by the operators <code>+</code> or <code>-</code>, must be separated from the operator with whitespace or parentheses in the source:</p>

```c
int x = 0xE+2;   // error
int y = 0xa+2;   // OK
int z = 0xE +2;  // OK
int q = (0xE)+2; // OK
```

<p>Otherwise, a single invalid preprocessing number token is formed, which causes further analysis to fail.</p>

<h3 id="Example">Example</h3>

```c
#include <inttypes.h>
#include <stdio.h>
 
int main(void)
{
    printf("123 = %d\n", 123);
    printf("0123 = %d\n", 0123);
    printf("0x123 = %d\n", 0x123);
    printf("12345678901234567890ull = %llu\n", 12345678901234567890ull);
    // the type is a 64-bit type (unsigned long long or possibly unsigned long)
    // even without a long suffix
    printf("12345678901234567890u = %"PRIu64"\n", 12345678901234567890u );
 
    // printf("%lld\n", -9223372036854775808); // Error:
        // the value 9223372036854775808 cannot fit in signed long long, which
        // is the biggest type allowed for unsuffixed decimal integer constant
 
    printf("%llu\n", -9223372036854775808ull );
    // unary minus applied to unsigned value subtracts it from 2^64,
    // this gives unsigned 9223372036854775808
 
    printf("%lld\n", -9223372036854775807ll - 1);
    // correct way to form signed value -9223372036854775808
}
```

<p>Output:</p>

```text
123 = 123
0123 = 83
0x123 = 291
12345678901234567890ull = 12345678901234567890
12345678901234567890u = 12345678901234567890
9223372036854775808
-9223372036854775808
```
