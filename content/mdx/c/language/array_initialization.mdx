<p>When <a href="/reference/c/language/initialization/">initializing</a> an object of <a href="/reference/c/language/array/">array</a> type, the initializer must be either a <a href="/reference/c/language/string_literal/">string literal</a> (optionally enclosed in braces) or be a brace-enclosed list of initialized for array members:</p>

```text
= string-literal
= { expression , ... }
= { designator(optional) expression , ... }
= { }
```

<p class="li-note"><span class="li-num">1)</span>  string literal initializer for character and wide character arrays</p>

<p class="li-note"><span class="li-num">2)</span>  comma-separated list of constant<span class="std std-until std-c99">(until C99)</span> expressions that are initializers for array elements, optionally using array designators of the form <code>[</code> <em>constant-expression</em> <code>]</code> <code>=</code> <span class="std std-since std-c99">(since C99)</span></p>

<p class="li-note"><span class="li-num">3)</span>  empty initializer empty-initializes every element of the array</p>

<p>Arrays of known size and arrays of unknown size may be initialized, but not VLAs<span class="std std-since std-c99">(since C99)</span><span class="std std-until std-c23">(until C23)</span>. A VLA can only be empty-initialized.<span class="std std-since std-c23">(since C23)</span></p>

<p>All array elements that are not initialized explicitly are <a href="/reference/c/language/initialization/#Empty_initialization">empty-initialized</a>.</p>

<h3 id="Initialization_from_strings">Initialization from strings</h3>

<p><a href="/reference/c/language/string_literal/">String literal</a> (optionally enclosed in braces) may be used as the initializer for an array of matching type:</p>

<ul>
<li>
<p>ordinary string literals</p>

and UTF-8 string literals<span class="std std-since std-c11">(since C11)</span>

<p>can initialize arrays of any character type (</p>

<code>char</code>

<p>,</p>

<code>signed char</code>

<p>,</p>

<code>unsigned char</code>

<p>)</p>
</li>
<li>
<p>L-prefixed wide string literals can be used to initialize arrays of any type compatible with (ignoring cv-qualifications)</p>

wchar_t
</li>
</ul>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span></p><ul>
<li>
<p>u-prefixed wide string literals can be used to initialize arrays of any type compatible with (ignoring cv-qualifications)</p>

char16_t
</li>
<li>
<p>U-prefixed wide string literals can be used to initialize arrays of any type compatible with (ignoring cv-qualifications)</p>

char32_t
</li>
</ul></aside>

<p>Successive bytes of the string literal or wide characters of the wide string literal, including the terminating null byte/character, initialize the elements of the array:</p>

```c
char str[] = "abc"; // str has type char[4] and holds 'a', 'b', 'c', '\0'
wchar_t wstr[4] = L"猫"; // str has type wchar_t[4] and holds L'猫', '\0', '\0', '\0'
```

<p>If the size of the array is known, it may be one less than the size of the string literal, in which case the terminating null character is ignored:</p>

```c
char str[3] = "abc"; // str has type char[3] and holds 'a', 'b', 'c'
```

<p>Note that the contents of such array are modifiable, unlike when accessing a string literal directly with <code>char* str = &quot;abc&quot;;</code>.</p>

<h3 id="Initialization_from_brace-enclosed_lists">Initialization from brace-enclosed lists</h3>

<p>When an array is initialized with a brace-enclosed list of initializers, the first initializer in the list initializes the array element at index zero (unless a designator is specified)<span class="std std-since std-c99">(since C99)</span>, and each subsequent initializer without a designator <span class="std std-since std-c99">(since C99)</span>initializes the array element at index one greater than the one initialized by the previous initializer.</p>

```c
int x[] = {1,2,3}; // x has type int[3] and holds 1,2,3
int y[5] = {1,2,3}; // y has type int[5] and holds 1,2,3,0,0
int z[4] = {1}; // z has type int[4] and holds 1,0,0,0
int w[3] = {0}; // w has type int[3] and holds all zeroes
```

<p>It's an error to provide more initializers than elements when initializing an array of known size (except when initializing character arrays from string literals).</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>A designator causes the following initializer to initialize of the array element described by the designator. Initialization then continues forward in order, beginning with the next element after the one described by the designator.</p>

```c
int n[5] = {[4]=5,[0]=1,2,3,4}; // holds 1,2,3,4,5
 
int a[MAX] = { // starts initializing a[0] = 1, a[1] = 3, ...
    1, 3, 5, 7, 9, [MAX-5] = 8, 6, 4, 2, 0
};
// for MAX=6,  array holds 1,8,6,4,2,0
// for MAX=13, array holds 1,3,5,7,9,0,0,0,8,6,4,2,0 ("sparse array")
```</aside>

<p>When initializing an array of unknown size, the largest subscript for which an initializer is specified determines the size of the array being declared.</p>

<h3 id="Nested_arrays">Nested arrays</h3>

<p>If the elements of an array are arrays, structs, or unions, the corresponding initializers in the brace-enclosed list of initializers are any initializers that are valid for those members, except that their braces may be omitted as follows:</p>

<p>If the nested initializer begins with an opening brace, the entire nested initializer up to its closing brace initializes the corresponding array element:</p>

```c
int y[4][3] = { // array of 4 arrays of 3 ints each (4x3 matrix)
    { 1 },      // row 0 initialized to {1, 0, 0}
    { 0, 1 },   // row 1 initialized to {0, 1, 0}
    { [2]=1 },  // row 2 initialized to {0, 0, 1}
};              // row 3 initialized to {0, 0, 0}
```

<p>If the nested initializer does not begin with an opening brace, only enough initializers from the list are taken to account for the elements or members of the sub-array, struct or union; any remaining initializers are left to initialize the next array element:</p>

```c
int y[4][3] = {    // array of 4 arrays of 3 ints each (4x3 matrix)
1, 3, 5, 2, 4, 6, 3, 5, 7 // row 0 initialized to {1, 3, 5}
};                        // row 1 initialized to {2, 4, 6}
                          // row 2 initialized to {3, 5, 7}
                          // row 3 initialized to {0, 0, 0}
 
struct { int a[3], b; } w[] = { { 1 }, 2 }; // array of structs
   // { 1 } is taken to be a fully-braced initializer for element #0 of the array
   // that element is initialized to { {1, 0, 0}, 0}
   // 2 is taken to be the first initialized for element #1 of the array
   // that element is initialized { {2, 0, 0}, 0}
```

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>Array designators may be nested; the bracketed constant expression for nested arrays follows the bracketed constant expression for the outer array:</p>

```c
int y[4][3] = {[0][0]=1, [1][1]=1, [2][0]=1};  // row 0 initialized to {1, 0, 0}
                                               // row 1 initialized to {0, 1, 0}
                                               // row 2 initialized to {1, 0, 0}
                                               // row 3 initialized to {0, 0, 0}
```</aside>

<h3 id="Notes">Notes</h3>

<p>The <a href="/reference/c/language/eval_order/">order of evaluation</a> of subexpressions in an array initializer is indeterminately sequenced in C (but not in C++ since C++11):</p>

```c
int n = 1;
int a[2] = {n++, n++}; // unspecified, but well-defined behavior,
                       // n is incremented twice (in arbitrary order)
                       // a initialized to {1, 2} and to {2, 1} are both valid
puts((char[4]){'0'+n} + n++); // undefined behavior:
                              // increment and read from n are unsequenced
```

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p>In C, the braced list of an initializer cannot be empty. C++ allows empty list:</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>An empty initializer can be used to initialize an array:</p></aside>

```c
int a[3] = {0}; // valid C and C++ way to zero-out a block-scope array
int a[3] = {}; // valid C++ way to zero-out a block-scope array; valid in C since C23
```

<p>As with all other <a href="/reference/c/language/initialization/">initialization</a>, every expression in the initializer list must be a <a href="/reference/c/language/constant_expression/">constant expression</a> when initializing arrays of static or thread-local <a href="/reference/c/language/storage_duration/">storage duration</a>:</p>

```c
static char* p[2] = {malloc(1), malloc(2)}; // error
```

<h3 id="Example">Example</h3>

```c
int main(void)
{
    // The following four array declarations are the same
    short q1[4][3][2] = {
        { 1 },
        { 2, 3 },
        { 4, 5, 6 }
    };
 
    short q2[4][3][2] = {1, 0, 0, 0, 0, 0, 2, 3, 0, 0, 0, 0, 4, 5, 6};
 
    short q3[4][3][2] = {
        {
            { 1 },
        },
        {
            { 2, 3 },
        },
        {
            { 4, 5 },
            { 6 },
        }
    };
 
    short q4[4][3][2] = {1, [1]=2, 3, [2]=4, 5, 6};
 
 
    // Character names can be associated with enumeration constants
    // using arrays with designators:
    enum { RED, GREEN, BLUE };
    const char *nm[] = {
        [RED] = "red",
        [GREEN] = "green",
        [BLUE] = "blue",
    };
}
```
