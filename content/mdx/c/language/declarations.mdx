<p>A <em>declaration</em> is a C language construct that introduces one or more <a href="/reference/c/language/identifier/">identifiers</a> into the program and specifies their meaning and properties.</p>

<p>Declarations may appear in any scope. Each declaration ends with a semicolon (just like <a href="/reference/c/language/statements/">a statement</a>) and consists of two<span class="std std-until std-c23">(until C23)</span>three<span class="std std-since std-c23">(since C23)</span> distinct parts:</p>

```text
specifiers-and-qualifiers declarators-and-initializers (optional) ;
attr-spec-seq specifiers-and-qualifiers declarators-and-initializers ;
attr-spec-seq ;
```

<p>where</p>

<table class="ref-table ref-params">

<ul>

</ul>

<p class="li-note"><span class="li-num">1,2)</span>  Simple declaration. Introduces one or more identifiers which denotes objects, functions, struct/union/enum tags, typedefs, or enumeration constants.</p>

<p class="li-note"><span class="li-num">3)</span>  Attribute declaration. Does not declares any identifier, and has implementation-defined meaning if the meaning is not specified by the standard.</p>

<p>For example,</p>

```c
int a, *b=NULL; // "int" is the type specifier,
                // "a" is a declarator
                // "*b" is a declarator and NULL is its initializer
const int *f(void); // "int" is the type specifier
                    // "const" is the type qualifier
                    // "*f(void)" is the declarator
enum COLOR {RED, GREEN, BLUE} c; // "enum COLOR {RED, GREEN, BLUE}" is the type specifier
                                 // "c" is the declarator
```

<p>The type of each identifier introduced in a declaration is determined by a combination of the type specified by the <em>type specifier</em> and the type modifications applied by its <em>declarator</em>. The type of a variable might also be inferred if <code>auto</code> specifier is used.<span class="std std-since std-c23">(since C23)</span></p>

<p><a href="/reference/c/language/attributes/">Attributes</a><span class="std std-since std-c23">(since C23)</span> may appear in <em>specifiers-and-qualifiers</em>, in which case they apply to the type determined by the preceding specifiers.</p>

<h3 id="Declarators">Declarators</h3>

<p>Each declarator is one of the following:</p>

```text
identifier attr-spec-seq (optional)
( declarator )
* attr-spec-seq (optional) qualifiers (optional) declarator
noptr-declarator [ static(optional) qualifiers (optional) expression ] noptr-declarator [ qualifiers (optional) * ]
noptr-declarator ( parameters-or-identifiers )
```

<p class="li-note"><span class="li-num">1)</span>  the identifier that this declarator introduces.</p>

<p class="li-note"><span class="li-num">2)</span>  any declarator may be enclosed in parentheses; this is required to introduce pointers to arrays and pointers to functions.</p>

<p class="li-note"><span class="li-num">3)</span>  <a href="/reference/c/language/pointer/">pointer declarator</a>: the declaration <code>S * cvr D</code>; declares <code>D</code> as a <em>cvr</em>-qualified pointer to the type determined by <code>S</code>.</p>

<p class="li-note"><span class="li-num">4)</span>  <a href="/reference/c/language/array/">array declarator</a>: the declaration <code>S D[N]</code> declares <code>D</code> as an array of <code>N</code> objects of the type determined by <code>S</code>. <em>noptr-declarator</em> is any other declarator except unparenthesized pointer declarator.</p>

<p class="li-note"><span class="li-num">5)</span>  <a href="/reference/c/language/function_declaration/">function declarator</a>: the declaration <code>S D(params)</code> declared <code>D</code> as a function taking the parameters <code>params</code> and returning <code>S</code>. <em>noptr-declarator</em> is any other declarator except unparenthesized pointer declarator.</p>

<p>The reasoning behind this syntax is that when the identifier declared by the declarator appears in an expression of the same form as the declarator, it would have the type specified by the type specifier sequence.</p>

```c
struct C
{
    int member; // "int" is the type specifier
                // "member" is the declarator
} obj, *pObj = &obj;
// "struct C { int member; }" is the type specifier
// declarator "obj" defines an object of type struct C
// declarator "*pObj" declares a pointer to C,
// initializer "= &obj" provides the initial value for that pointer
 
int a = 1, *p = NULL, f(void), (*pf)(double);
// the type specifier is "int"
// declarator "a" defines an object of type int
//   initializer "=1" provides its initial value
// declarator "*p" defines an object of type pointer to int
//   initializer "=NULL" provides its initial value
// declarator "f(void)" declares a function taking void and returning int
// declarator "(*pf)(double)" defines an object of type pointer
//   to function taking double and returning int
 
int (*(*foo)(double))[3] = NULL;
// the type specifier is int
// 1. declarator "(*(*foo)(double))[3]" is an array declarator:
//    the type declared is "/nested declarator/ array of 3 int"
// 2. the nested declarator is "*(*foo)(double))", which is a pointer declarator
//    the type declared is "/nested declarator/ pointer to array of 3 int"
// 3. the nested declarator is "(*foo)(double)", which is a function declarator
//    the type declared is "/nested declarator/ function taking double and returning
//        pointer to array of 3 int"
// 4. the nested declarator is "(*foo)" which is a (parenthesized, as required by
//        function declarator syntax) pointer declarator.
//    the type declared is "/nested declarator/ pointer to function taking double
//        and returning pointer to array of 3 int"
// 5. the nested declarator is "foo", which is an identifier.
// The declaration introduces the identifier "foo" to refer to an object of type
// "pointer to function taking double and returning pointer to array of 3 int"
// The initializer "= NULL" provides the initial value of this pointer.
 
// If "foo" is used in an expression of the form of the declarator, its type would be
// int.
int x = (*(*foo)(1.2))[0];
```

<p>The end of every declarator that is not part of another declarator is a <a href="/reference/c/language/eval_order/">sequence point</a>.</p>

<p>In all cases, <em>attr-spec-seq</em> is an optional sequence of <a href="/reference/c/language/attributes/">attributes</a><span class="std std-since std-c23">(since C23)</span>. When appearing immediately after the identifier, it applies to the object or function being declared.</p>

<h3 id="Definitions">Definitions</h3>

<p>A <em>definition</em> is a declaration that provides all information about the identifiers it declares.</p>

<p>Every declaration of an <a href="/reference/c/language/enum/">enum</a> or a <a href="/reference/c/language/typedef/">typedef</a> is a definition.</p>

<p>For functions, a declaration that includes the function body is a <a href="/reference/c/language/function_definition/">function definition</a>:</p>

```c
int foo(double); // declaration
int foo(double x) { return x; } // definition
```

<p>For objects, a declaration that allocates storage (<a href="/reference/c/language/storage_duration/">automatic or static</a>, but not extern) is a definition, while a declaration that does not allocate storage (<a href="/reference/c/language/extern/">external declaration</a>) is not.</p>

```c
extern int n; // declaration
int n = 10; // definition
```

<p>For <a href="/reference/c/language/struct/">structs</a> and <a href="/reference/c/language/union/">unions</a>, declarations that specify the list of members are definitions:</p>

```c
struct X; // declaration
struct X { int n; }; // definition
```

<h3 id="Redeclaration">Redeclaration</h3>

<p>A declaration cannot introduce an identifier if another declaration for the same identifier in the same <a href="/reference/c/language/scope/">scope</a> appears earlier, except that</p>

<ul>
<li>
<p>Declarations of objects</p>

<a href="/reference/c/language/storage_duration/">with linkage</a>

<p>(external or internal) can be repeated:</p>
</li>
</ul>

```c
extern int x;
int x = 10; // OK
extern int x; // OK
 
static int n;
static int n = 10; // OK
static int n; // OK
```

<ul>
<li>
<p>Non-VLA</p>

<a href="/reference/c/language/typedef/">typedef</a>

<p>can be repeated as long as it names the same type:</p>
</li>
</ul>

```c
typedef int int_t;
typedef int int_t; // OK
```

<ul>
<li>
<a href="/reference/c/language/struct/">struct</a>

<p>and</p>

<a href="/reference/c/language/union/">union</a>

<p>declarations can be repeated:</p>
</li>
</ul>

```c
struct X;
struct X { int n; };
struct X;
```

<p>These rules simplify the use of header files.</p>

<h3 id="Notes">Notes</h3>

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c99">(until C99)</span></p><p>In C89, declarations within any <a href="/reference/c/language/statements/#Compound_statements">compound statement</a> (block scope) must appear in the beginning of the block, before any <a href="/reference/c/language/statements/">statements</a>.</p>

<p>Also, in C89, functions returning <code>int</code> may be implicitly declared by the <a href="/reference/c/language/operator_other/#Function_call">function call operator</a> and function parameters of type <code>int</code> do not have to be declared when using old-style <a href="/reference/c/language/function_definition/">function definitions</a>.</p></aside>

<p>Empty declarators are prohibited; a simple declaration must have at least one declarator or declare at least one struct/union/enum tag, or introduce at least one enumeration constant.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>If any part of a declarator is a <a href="/reference/c/language/array/">variable-length array</a> (VLA) declarator, the entire declarator's type is known as "variably-modified type". Types defined from variably-modified types are also variably modified (VM).</p>

<p>Declarations of any variably-modified types may appear only at <a href="/reference/c/language/scope/">block scope</a> or function prototype scope and cannot be members of structs or unions. Although VLA can only have automatic or allocated <a href="/reference/c/language/storage_duration/">storage duration</a>, a VM type such as a pointer to a VLA may be static. There are other restrictions on the use of VM types, see <a href="/reference/c/language/goto/">goto</a>, <a href="/reference/c/language/switch/">switch</a>. <a href="/reference/c/program/longjmp/">longjmp</a></p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c11">(since C11)</span></p><p><a href="/reference/c/language/static_assert/">static_asserts</a> are considered to be declarations from the point of view of the C grammar (so that they may appear anywhere a declaration may appear), but they do not introduce any identifiers and do not follow the declaration syntax.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p><a href="/reference/c/language/attributes/">Attribute</a> declarations are also considered to be declarations (so that they may appear anywhere a declaration may appear), but they do not introduce any identifiers. A single <code>;</code> without <em>attr-spec-seq</em> is not an attribute declaration, but a statement.</p></aside>
