<p>Each individual type in the C <a href="/reference/c/language/compatible_type/">type system</a> has several <em>qualified</em> versions of that type, corresponding to one, two, or all three of the <a href="/reference/c/language/const/"><code>const</code></a>, <code>volatile</code>, and, for pointers to object types, <a href="/reference/c/language/restrict/"><code>restrict</code></a> qualifiers. This page describes the effects of the <code>volatile</code> qualifier.</p>

<p>Every access (both read and write) made through an lvalue expression of volatile-qualified type is considered an observable side effect for the purpose of optimization and is evaluated strictly according to the rules of the abstract machine (that is, all writes are completed at some time before the next sequence point). This means that within a single thread of execution, a volatile access cannot be optimized out or reordered relative to another visible side effect that is separated by a <a href="/reference/c/language/eval_order/">sequence point</a> from the volatile access.</p>

<p>A cast of a non-volatile value to a volatile type has no effect. To access a non-volatile object using volatile semantics, its address must be cast to a pointer-to-volatile and then the access must be made through that pointer.</p>

<p>Any attempt to read or write to an object whose type is volatile-qualified through a non-volatile lvalue results in undefined behavior:</p>

```c
volatile int n = 1; // object of volatile-qualified type
int* p = (int*)&n;
int val = *p; // undefined behavior
```

<p>A member of a volatile-qualified structure or union type acquires the qualification of the type it belongs to (both when accessed using the <code>.</code> operator or the <code>-&gt;</code> operator):</p>

```c
struct s { int i; const int ci; } s;
// the type of s.i is int, the type of s.ci is const int
volatile struct s vs;
// the types of vs.i and vs.ci are volatile int and const volatile int
```

<aside class="revision"><p class="rev-mark"><span class="std std-until std-c23">(until C23)</span></p><p>If an array type is declared with the volatile type qualifier (through the use of <a href="/reference/c/language/typedef/"><code>typedef</code></a>), the array type is not volatile-qualified, but its element type is.</p></aside>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c23">(since C23)</span></p><p>An array type and its element type are always considered to be identically volatile-qualified.</p></aside>

```c
typedef int A[2][3];
volatile A a = {{4, 5, 6}, {7, 8, 9}}; // array of array of volatile int
int* pi = a[0]; // Error: a[0] has type volatile int*
void *unqual_ptr = a; // OK until C23; error since C23
// Notes: clang applies the rule in C++/C23 even in C89-C17 modes
```

<p>If a function type is declared with the volatile type qualified (through the use of <a href="/reference/c/language/typedef/"><code>typedef</code></a>), the behavior is undefined.</p>

<aside class="revision"><p class="rev-mark"><span class="std std-since std-c99">(since C99)</span></p><p>In a function declaration, the keyword <code>volatile</code> may appear inside the square brackets that are used to declare an array type of a function parameter. It qualifies the pointer type to which the array type is transformed.</p>

<p>The following two declarations declare the same function:</p>

```c
void f(double x[volatile], const double y[volatile]);
void f(double * volatile x, const double * volatile y);
```</aside>

<p>A pointer to a non-volatile type can be implicitly converted to a pointer to the volatile-qualified version of the same or <a href="/reference/c/language/compatible_type/">compatible</a> type. The reverse conversion requires a cast expression.</p>

```c
int* p = 0;
volatile int* vp = p; // OK: adds qualifiers (int to volatile int)
p = vp; // Error: discards qualifiers (volatile int to int)
p = (int*)vp; // OK: cast
```

<p>Note that pointer to pointer to <code>T</code> is not convertible to pointer to pointer to <code>volatile T</code>; for two types to be compatible, their qualifications must be identical:</p>

```c
char *p = 0;
volatile char **vpp = &p; // Error: char* and volatile char* are not compatible types
char * volatile *pvp = &p; // OK, adds qualifiers (char* to char*volatile)
```

<h3 id="Uses_of_volatile">Uses of volatile</h3>

<div class="li-note"><span class="li-num">1)</span>

<a href="/reference/c/language/static_storage_duration/"><code>static</code></a>

<code>volatile</code>

<p>objects model memory-mapped I/O ports, and</p>

<code>static</code>

<code>const</code>

<code>volatile</code>

<p>objects model memory-mapped input ports, such as a real-time clock:</p>

```c
volatile short *ttyport = (volatile short*)TTYPORT_ADDR;
for(int i = 0; i < N; ++i)
    *ttyport = a[i]; // *ttyport is an lvalue of type volatile short
```</div>

<p class="li-note"><span class="li-num">2)</span>  <code>static</code> <code>volatile</code> objects of type <a href="/reference/c/program/sig_atomic_t/">sig_atomic_t</a> are used for communication with <a href="/reference/c/program/signal/">signal</a> handlers.</p>

<p class="li-note"><span class="li-num">3)</span>  <code>volatile</code> variables that are local to a function that contains an invocation of the <a href="/reference/c/program/setjmp/">setjmp</a> macro are the only local variables guaranteed to retain their values after <a href="/reference/c/program/longjmp/">longjmp</a> returns.</p>

<p class="li-note"><span class="li-num">4)</span>  In addition, volatile variables can be used to disable certain forms of optimization, e.g. to disable dead store elimination or constant folding for micro-benchmarks.</p>

<p>Note that volatile variables are not suitable for communication between threads; they do not offer atomicity, synchronization, or memory ordering. A read from a volatile variable that is modified by another thread without synchronization or concurrent modification from two unsynchronized threads is undefined behavior due to a data race.</p>

<h3 id="Example">Example</h3>

<p>demonstrates the use of volatile to disable optimizations</p>

```c
#include <stdio.h>
#include <time.h>
 
int main(void)
{
    clock_t t = clock();
    double d = 0.0;
    for (int n = 0; n < 10000; ++n)
        for (int m = 0; m < 10000; ++m)
            d += d * n * m; // reads from and writes to a non-volatile 
    printf("Modified a non-volatile variable 100m times. "
           "Time used: %.2f seconds\n",
           (double)(clock() - t)/CLOCKS_PER_SEC);
 
    t = clock();
    volatile double vd = 0.0;
    for (int n = 0; n < 10000; ++n)
        for (int m = 0; m < 10000; ++m) {
            double prod = vd * n * m; // reads from a volatile
            vd += prod; // reads from and writes to a volatile
        } 
    printf("Modified a volatile variable 100m times. "
           "Time used: %.2f seconds\n",
           (double)(clock() - t)/CLOCKS_PER_SEC);
}
```

<p>Possible output:</p>

```text
Modified a non-volatile variable 100m times. Time used: 0.00 seconds
Modified a volatile variable 100m times. Time used: 0.79 seconds
```
